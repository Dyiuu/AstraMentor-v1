# 项目五：集成知识与外部服务

## 岗位情境

某职业院校已经拥有课程知识库、学员档案服务和实训预约系统。产品经理希望学习助理既能引用教材回答，又能读取学生已掌握的知识点，并在学生确认后预约实训工位。你的任务不是重新实现向量检索或数据库，而是把现有能力包装成 Agent 可以安全调用、能够观察和测试的知识工具与业务工具。

真实工程中，外部系统的返回格式、延迟和权限各不相同。模型只看到工具说明，程序却必须承担身份鉴别、参数校验、超时、重试、脱敏和审计责任。本项目以“查教材—读进度—给建议—确认后预约”的岗位任务为主线，训练跨服务集成能力。

## 项目目标

完成后，你能够根据职责边界设计只读与写入工具；为 RAG、REST API 和数据库适配统一结果信封；把引用、错误类型和下一步建议作为结构化观察返回 Agent；用依赖注入替换真实服务完成离线测试；并能说明何时应该拒绝模型发起的高风险调用。

学习重点是接口治理，而不是某个厂商 SDK。你需要让工具在成功、无结果、可重试失败、永久失败和需要人工确认时都给出确定状态，使上层执行循环不会靠猜测继续行动。

## 项目产物与验收条件

- 输入：现有知识检索接口说明、学员身份上下文、预约 API 契约和一组教师编写的测试任务。
- 输出：三个工具的 Schema、适配器代码、权限矩阵、模拟服务、自动化测试与一次完整运行记录。
- 验收证据：检索答案包含可核对来源；越权读取被拒绝；写入在确认前不会执行；超时不会触发无限重试；日志能按 run_id 还原调用链且不含密钥。

| 验收项 | 通过标准 | 证据形式 |
|---|---|---|
| 知识工具 | 返回片段、课程、标题和行号 | JSON 结果与引用核对表 |
| 学员工具 | 只能读取当前授权学员 | 权限测试报告 |
| 预约工具 | 幂等且必须携带确认令牌 | 两次请求对比记录 |
| 故障处理 | 五种状态均被上层识别 | 单元测试输出 |
| 可观测性 | 调用耗时、状态和关联 ID 完整 | 脱敏日志样例 |

## 任务分析

首先绘制系统边界：Agent 只产生工具意图，工具层负责验证与执行，外部服务仍是事实来源。随后把知识检索的内部结果转换为稳定 DTO，避免把向量分数等实现细节直接暴露给模型。对学员档案采用服务端注入身份，禁止模型自己填写 user_id。预约属于有副作用操作，需要预览、确认和幂等键三道控制。

风险分析应覆盖网络抖动、旧版响应、空检索、权限过期和重复提交。可重试条件由状态码与错误类别决定，而不是由模型文本决定。每个适配器给出短小、可操作的错误信息，同时把详细异常留在受控日志中。

## 核心知识

### 工具适配层

适配层隔离外部接口变化，并把不同系统映射为统一语义。建议结果信封至少包含 `status`、`data`、`error_code`、`retryable`、`source` 与 `latency_ms`。上层只依赖这些稳定字段，底层可以从本地 BM25 换成托管检索，也可以升级预约服务版本。适配器不得悄悄吞掉异常，否则 Agent 会把缺失数据误判为事实。

### 身份、授权与作用域

认证说明“调用者是谁”，授权决定“能做什么”。学员标识应从服务器会话注入，工具 Schema 中不开放任意用户 ID。课程检索也要携带 course_id 白名单，防止模型跨科目拼接不相关材料。面向教师和学生的工具集合应分开注册，而非仅靠提示词要求模型自律。

### 引用与证据

知识工具的目标不是返回最长文本，而是返回足够回答的片段及稳定定位信息。来源字段包含课程 ID、材料 ID、标题路径、起止行和索引版本。最终答案中的主张要能映射到引用；低相关或证据冲突时，工具应返回“证据不足”，让 Agent 追问或转人工，不能补写看似合理的内容。

### 副作用与幂等性

读操作与写操作必须显式区分。预约工具先生成预览，界面展示日期、地点、资源和取消规则；用户确认后，服务端签发短期确认令牌。幂等键绑定用户、业务参数和操作类型，即使网络重试也只产生一条预约。补偿动作同样要记录权限和审计证据。

## 工程实现步骤

### 步骤一：定义跨工具结果契约

列出外部服务的成功与失败样例，将供应商字段转换为领域字段。为 `ok/not_found/needs_confirmation/retryable_error/denied` 定义枚举，约定可展示消息与内部诊断信息分离。使用 JSON Schema 验证模型可见参数，拒绝未声明字段和超长文本。

### 步骤二：封装只读知识和档案能力

知识适配器接收受控 course_id、query 和 top_k，限制 top_k 上限并保留安全来源。档案适配器从调用上下文取得 subject_id，只返回学习任务需要的最少字段。对两个适配器注入客户端接口、时钟和追踪器，使测试可替换为内存实现。

### 步骤三：实现确认式写入流程

把预约分成 `preview_booking` 与 `commit_booking`。预览不产生副作用，提交校验确认令牌、参数摘要、过期时间和幂等键。若预览后资源变化，返回冲突并要求重新确认，不能自动换到另一个时间段。

### 步骤四：建立契约与故障测试

保存外部 API 的脱敏样例作为契约夹具，覆盖字段缺失、类型改变、429、超时、401 和重复提交。断言程序只对安全的瞬时错误有限重试；写入请求在响应不确定时先查询幂等结果，而不是盲目重放。

### 步骤五：完成端到端演练

用固定测试任务运行 Agent，检查它先检索再读取进度，建议与证据一致，并在预约前停在人工确认节点。导出事件时间线、引用核验表和权限测试结果，邀请同学扮演审计员复查。

## 关键代码与配置

下面的示例展示统一信封和服务器端身份注入。生产环境还要配置连接池、熔断、追踪和真正的授权中间件。

```python
from dataclasses import dataclass

@dataclass
class ToolContext:
    run_id: str
    subject_id: str
    allowed_courses: set[str]

def search_course(args, ctx, retriever):
    course_id = args["course_id"]
    if course_id not in ctx.allowed_courses:
        return {"status": "denied", "retryable": False}
    hits = retriever.search(course_id, args["query"], min(args.get("top_k", 4), 6))
    if not hits:
        return {"status": "not_found", "data": [], "retryable": False}
    data = [{"text": h.text, "material_id": h.material_id,
             "heading": h.heading, "line_start": h.line_start,
             "line_end": h.line_end} for h in hits]
    return {"status": "ok", "data": data, "retryable": False}
```

工具说明要陈述适用场景、禁止场景和字段约束。例如知识工具只回答指定课程内容，不应被用于读取个人档案；预约提交工具必须由程序检测确认令牌，不能把“用户已经确认”作为普通布尔参数交给模型填写。

## 调试和常见故障

### 故障一：回答有引用但引用无法打开

- 现象：答案展示了材料名称，点击后定位到错误章节，或索引重建后行号越界。
- 原因：适配器只保存显示标题，未保存规范化材料 ID、索引版本和安全相对路径；缓存还混用了旧索引结果。
- 定位：根据 run_id 检查原始命中、索引版本与当前文件哈希，验证 line_start 到 line_end 是否落在同一来源文件。
- 修复：把稳定来源字段纳入 DTO；索引发布时原子切换版本并使旧缓存失效；返回前执行路径和行号范围校验。

### 故障二：网络超时导致重复预约

- 现象：用户只确认一次，预约系统却出现两条相同记录，Agent 日志中存在连续提交。
- 原因：客户端在响应丢失后把写请求当作普通可重试调用，且服务端没有使用业务幂等键。
- 定位：比对两次提交的确认令牌、参数摘要和请求 ID，检查超时分支是否先查询已存在结果。
- 修复：为提交生成稳定幂等键并由服务端唯一约束；超时后先查状态；超过一次不确定响应就进入人工处理，不再自主写入。

## 安全、成本与职业规范提示

密钥保存在服务端密钥管理或环境变量中，绝不能进入工具描述、模型上下文或前端代码。日志对姓名、手机号和学习档案做字段级脱敏，并设置访问控制与保留期限。跨用户查询必须在工具执行层拒绝，提示词不是授权系统。

控制检索 top_k、响应体大小、超时和最大重试数可以同时降低 Token 与外部调用成本。缓存只能用于权限无关或以授权主体隔离的数据；学习进度与预约结果不能被不同用户共享。工程人员应如实区分“外部服务无结果”和“模型不知道”，并保留人工申诉通道。

## 实训练习

1. 为知识工具加入课程白名单和 top_k 边界，编写越权与边界值测试。
2. 设计一个字段级脱敏器，验证嵌套对象中的手机号和邮箱不会进入日志。
3. 模拟预约服务先执行成功再丢失响应，证明幂等查询能找回原结果。
4. 构造来源行号越界的检索命中，让适配器返回安全错误而不是生成链接。
5. 对比直接暴露通用 HTTP 工具与注册三个领域工具的风险面和维护成本。
6. 绘制工具调用数据流，标注身份注入、授权、确认、审计与数据保留位置。

## 本项目小结

本项目把已有知识库、学员服务和预约系统变成了受控 Agent 工具。关键成果不是“接口能调用”，而是身份不会由模型伪造、写操作不会跳过确认、失败不会被误读为事实、知识结论可以回到原文。稳定适配层让上层工作流不依赖具体供应商，也为后续 MCP 接入和多智能体协作提供了清晰能力边界。
