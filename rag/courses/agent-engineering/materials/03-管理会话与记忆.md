# 项目三：管理会话与记忆

## 岗位情境

职业学习助理需要在多轮学习中记住学生正在学习的课程、当前知识点、已完成步骤和用户明确表达的偏好。试运行时，团队把全部历史消息每轮原样发送给模型，短会话尚可工作，长会话却出现成本快速增加、旧指令压过新任务、A 学生信息进入 B 学生回答等问题。另一个版本把模型生成的所有“记忆”永久保存，结果把一次猜测当成了学生事实。

你需要建立分层记忆系统：运行状态服务当前步骤，会话历史支持近期对话，摘要控制上下文长度，长期记忆只保存经过规则确认且有来源的稳定事实。记忆的写入、检索、更新和删除都由应用控制，并以用户、课程和会话作为隔离键。最终实现要能解释一条记忆从哪里来、何时过期、为什么被放进本轮上下文。

## 项目目标

- 能区分运行状态、短期会话、摘要、长期记忆和外部知识库。
- 能设计带租户、用户、课程、来源、置信状态和生命周期的记忆记录。
- 能用确定性规则筛选记忆候选，避免把模型猜测直接当成事实。
- 能按相关性、时效性、权限和上下文预算选择记忆。
- 能实现更正、遗忘、冲突处理和隐私审计，并用多用户测试验证隔离。

完成后，学习者应能回答“为什么不能把聊天记录等同于记忆”“摘要为何不能替代原始审计事件”，并能在恢复会话时保持课程与知识点一致。

## 项目产物与验收条件

- 输入：会话事件、当前用户/课程上下文、记忆写入策略和上下文 Token 预算。
- 输出：会话仓库、长期记忆仓库、摘要器接口、记忆选择器和删除/更正操作。
- 验收证据：同用户续学、跨课程隔离、跨用户隔离、偏好更正、过期删除和摘要恢复六组测试记录。
- 每条长期记忆必须包含来源事件、创建时间、作用域和可删除标识；无来源的模型推断不得持久化为事实。
- 上下文构建报告要列出采用与丢弃的记忆及原因，便于定位错误。

## 任务分析

记忆系统包含“写什么、存在哪里、何时取出、如何失效”四个决定。只实现数据库写入并不能形成可靠记忆。学习状态需要高一致性，偏好可以后写覆盖，模型摘要则是可重建派生物；不同数据应采用不同更新规则。先建立数据分类与隔离键，再选择存储技术。

### 作用域设计

最小作用域键为 `tenant_id/user_id/course_id/session_id`。租户隔离优先于语义相关性，即使另一用户的记忆更“相关”也不得被检索。课程级状态不应被同名课程覆盖；会话摘要只属于产生它的历史区间。长期偏好可跨会话，但必须允许用户查看和删除。

## 核心知识

### 五类上下文数据

运行状态是程序事实，如步骤号和已执行工具；短期历史是最近消息与工具事件；摘要是对较旧历史的压缩表示；长期记忆是经确认的稳定用户事实或偏好；知识库是课程或组织资料。知识库讲“世界与课程”，记忆讲“这个用户与这次工作”。把它们混在同一向量集合中会破坏权限和更新语义。

### 记忆写入策略

候选来源可以是用户明确陈述、确定性业务事件和人工确认。模型可以建议候选，但程序要检查来源、类别和冲突。诸如“用户不理解循环”可能只是当次表现，应保存为带时间的学习观察而非永久能力标签；“用户希望示例使用 Python”是明确偏好，可以在确认后跨会话使用。

每条记录需要稳定 ID、作用域、类型、内容、来源事件 ID、创建/更新时间、过期时间和状态。敏感类别还需记录用途与同意依据。长期记忆不要保存原始访问令牌、完整身份证件或无关隐私。

### 上下文选择与预算

选择器先做权限和作用域过滤，再按任务相关性与时效性排序，最后在预算内装配。优先级通常是系统约束、当前运行状态、最新用户目标、必要课程证据、相关记忆、摘要和少量近期消息。不能先检索全库再让模型自行忽略越权内容，因为泄露已经发生。

### 摘要、冲突与遗忘

摘要是有损派生物，应保存覆盖消息范围和生成版本；重要业务事实仍引用原事件。新记忆与旧记忆冲突时，按类型选择策略：偏好采用最近明确声明，业务状态由权威系统覆盖，主观观察保留时间线而非互相删除。用户要求遗忘时，需要删除长期记录、使相关缓存失效，并避免从旧摘要再次恢复。

## 工程实现步骤

### 步骤一：定义记忆记录和隔离查询

建立 `MemoryRecord`，把内容与用户、课程、类型、来源和生命周期绑定。仓库查询必须要求可信上下文，不允许调用方只传自由文本。先使用内存或 JSON 仓库完成契约测试，再替换数据库。

### 步骤二：实现候选写入与确认

从用户明确语句和业务事件生成候选。规则允许低敏感偏好自动写入，学习能力判断必须标为观察，高敏感内容拒绝。候选若与现有记录冲突，返回确认请求而不是静默覆盖。

### 步骤三：实现预算化上下文选择器

按权限、课程、状态过滤候选，计算简单相关分与新鲜度，估算字符或 Token 成本。选择结果同时返回 `included` 与 `excluded_reason`，以便调试。摘要只覆盖已封存的历史段，最新消息保持原文。

### 步骤四：实现更正、遗忘和恢复测试

为用户提供列出、修改和删除记忆的接口。删除后清理查询缓存，重新构建上下文并断言目标内容消失。创建两个用户、两个课程和同名会话，验证所有组合互不读取。

## 关键代码与配置

```python
from dataclasses import dataclass

@dataclass
class MemoryRecord:
    memory_id: str
    user_id: str
    course_id: str
    kind: str
    content: str
    source_event_id: str
    active: bool = True

class MemoryStore:
    def __init__(self):
        self.rows = []

    def add(self, record):
        self.rows.append(record)

    def find(self, user_id, course_id):
        return [row for row in self.rows
                if row.active and row.user_id == user_id
                and row.course_id == course_id]

    def forget(self, memory_id, user_id):
        for row in self.rows:
            if row.memory_id == memory_id and row.user_id == user_id:
                row.active = False
```

示例突出对象级过滤。生产系统还要校验租户、记录删除审计、使用原子更新并限制内容类型，不能把用户 ID 交给模型生成。

## 调试和常见故障

### 故障一：恢复会话后出现另一门课程内容

- 现象：学生恢复 Agent 课程会话，却得到低代码课程的步骤摘要或偏好。
- 原因：查询只使用用户 ID 和会话标题，没有把稳定课程 ID 纳入隔离键；同名标题发生碰撞。
- 定位：查看记忆选择报告和存储键，比较被选记录的 course_id 与当前会话快照。
- 修复：课程模式强制使用稳定 course_id；历史恢复沿用原 ID，标题只用于显示，不参与授权和唯一性判断。

### 故障二：用户更正偏好后旧偏好仍被采用

- 现象：用户已改为“示例使用 Java”，上下文仍同时注入旧的 Python 偏好。
- 原因：新记录采用追加模式，选择器没有处理同类记忆的版本与失效状态，缓存也未清理。
- 定位：按 kind 和更新时间列出记录，检查旧记录 active 状态以及缓存键是否包含版本。
- 修复：明确偏好采用替换语义；写入新值时原子失效旧值、增加版本并清理相关缓存。

## 安全、成本与职业规范提示

记忆是持续存在的用户数据，不是普通提示文本。只收集完成学习任务所需的信息，说明用途和保留期，并提供查看、更正与删除能力。权限过滤必须在读取数据时完成，不能依赖模型自我约束。日志只记录记忆 ID、类别和策略结果，避免再次复制敏感正文。

全量历史会增加 Token 成本并降低重点清晰度。使用可重建摘要与预算选择器，但要保留重要事件引用。任何自动总结都可能失真，涉及成绩、资格和身份的事实必须回到权威记录核验，不能依据摘要直接做高影响判断。

## 实训练习

1. 设计三种记忆类型的更新策略：覆盖、追加时间线、禁止长期保存。
2. 实现含课程 ID 的选择器，并编写两用户两课程的参数化隔离测试。
3. 给摘要增加覆盖消息范围和版本，模拟摘要器升级后的重建。
4. 实现“列出我的记忆”和“忘记这条记录”，验证缓存同步失效。
5. 为上下文预算生成报告，比较保留 20 条历史与摘要方案的成本和信息损失。

## 本项目小结

Agent 记忆的价值不在“记得越多”，而在正确作用域中保留可核验、可更新、可删除的信息。运行状态、历史、摘要、长期记忆和知识库承担不同职责；权限过滤先于相关性；摘要服务预算而不替代证据。可靠记忆让 Agent 能继续工作，也让用户能够控制自己的数据。
