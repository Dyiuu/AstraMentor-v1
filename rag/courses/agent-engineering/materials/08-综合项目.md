# 项目八：综合项目——交付可观测职业学习助理

## 岗位情境

你所在的 AI 职业教育团队要在两周后进行校内试点。学习助理需根据课程知识库回答问题，读取当前学生进度，生成下一步学习建议，并可在学生确认后创建学习任务。教师要求随时看见系统正在做什么、引用来自哪里；学生要能取消长任务；运维人员要能依据运行 ID 定位失败；任何写操作都不能由模型擅自完成。

这是课程综合交付，不是把前七个项目代码简单拼接。你需要从岗位验收反推架构，选择单 Agent、工作流和必要的专业角色，建立状态、工具、MCP 接入、记忆、人工确认、可观测性与恢复策略。最终成果必须能在模型或外部服务异常时安全失败，并用测试证据说明系统边界。

## 项目目标

完成后，你能够独立交付一个可演示、可测试、可中断和可审计的 Agent 应用；能将知识检索、学习状态和任务创建封装为最小权限工具；用确定性控制流约束模型决策；对工具、记忆和外部协议实施安全治理；并通过场景验收、故障注入和岗位答辩说明设计取舍。

综合项目还要求建立“完成定义”：模型输出自然语言不等于任务完成。只有建议包含证据、状态更新成功且审计事件落盘，运行才能进入 completed；其他情况进入 incomplete、needs_human 或 failed。

## 项目产物与验收条件

- 输入：课程知识库、学生学习状态样例、任务服务契约、用户故事、安全要求和二十个验收场景。
- 输出：架构与威胁模型、可运行应用、配置样例、测试套件、追踪报告、用户操作说明和五分钟岗位演示。
- 验收证据：知识回答与学习主题一致且可引用；用户可取消；创建任务前显示预览并确认；重试不重复写入；断网和模型错误给出明确恢复路径；日志能按 run_id 还原状态迁移且无凭据。

| 验收项 | 通过标准 | 必交证据 |
|---|---|---|
| 任务闭环 | 查询、建议、确认、写入状态一致 | 端到端录像与状态快照 |
| 知识可信 | 关键主张有安全来源，证据不足会拒答 | 引用核验表 |
| 人机协同 | 高风险动作可预览、取消和恢复 | 确认/取消测试 |
| 可观测性 | 模型、工具、移交和错误形成时间线 | 脱敏 trace |
| 工程质量 | 核心逻辑有离线自动化测试 | 测试报告与覆盖清单 |
| 安全边界 | 最小权限、密钥隔离、输入输出限额 | 威胁模型与攻击演练 |

## 任务分析

将用户故事拆为四条主路径：课程问答只需知识工具；学习诊断读取状态后提出建议；创建任务在人工确认后写入；教师审计只读取脱敏事件。跨路径共享 run_id 和受控会话摘要，不共享所有原始工具结果。确定性路由优先识别取消、确认和状态查询，开放式学习问题才交给模型规划。

架构采用中心状态机管理 `intake/retrieve/plan/confirm/commit/respond` 阶段。课程教练和安全检查器只有在复杂建议场景才被调用，避免无意义多 Agent 成本。每次运行有截止时间、最大模型调用数、最大工具调用数和 Token 预算。外部任务服务通过适配器或受控 MCP Server 接入。

## 核心知识

### 从完成定义反推状态机

为每种终态定义可机器验证的条件。`completed` 必须有最终产物 ID 或可核验回答；`incomplete` 表示预算或时间用尽但状态完整；`needs_human` 表示需要用户选择、授权或处理冲突；`failed` 表示不可安全恢复的技术错误。状态转换附带触发事件和证据，不允许模型直接修改终态。

### 主题一致性与证据绑定

学习会话把 course_id、material_id、active_topic_id 和索引版本作为显式状态。生成新教学内容或问题前读取同一快照，问题必须引用当前主题；状态切换只有在教学内容保存成功后发生。知识命中附带标题路径与行号，答案生成后用引用检查器验证来源属于当前课程，防止旧会话结果串入。

### 可中断执行

取消不是前端隐藏加载图标。服务端保存取消标志，执行循环在模型调用前、工具调用前和写入前检查；流式响应断开后决定取消运行或进入后台，策略必须明确。已开始的副作用使用幂等键和状态查询收敛，不能假设网络断开等于业务未执行。

### 人工确认与恢复

确认页展示工具名称、规范化参数、影响对象、成本和可撤销性。确认令牌绑定用户、run_id、动作摘要和有效期，参数变化后必须重新确认。检查点保存到副作用之前，进程重启后恢复为等待确认，而不是自动提交。拒绝与过期也作为正式事件记录。

### 追踪与评测

追踪包括阶段耗时、模型用量、工具状态、引用、handoff、确认和终态。敏感内容采用摘要或哈希，不把完整学生档案写入普通日志。离线评测覆盖路线正确率、引用正确率、主题一致率、任务重复率和安全违规；线上指标监控延迟、失败率、用户取消和人工接管。

## 工程实现步骤

### 步骤一：冻结验收契约和测试数据

把二十个场景分为正常、边界、故障和攻击四组，每个场景写出输入、预期阶段、允许工具、最终状态和证据。创建匿名学生状态与内存任务服务，确保无网络也能运行核心回归测试。将真实模型测试单独标记为可选冒烟测试。

### 步骤二：实现状态、事件和受控路由

定义不可混淆的 run_id、course_id、topic_id、阶段、预算与取消字段。所有转换通过单一 reducer 完成并追加事件。程序优先处理取消、确认和拒绝；模型的计划输出使用 Schema 校验，只能提出白名单行动。

### 步骤三：注册最小工具与知识证据

为知识检索、读取本人进度、预览任务和提交任务建立独立工具。身份由服务器注入，写工具需要确认令牌与幂等键。检索工具返回安全相对来源和行号；回答没有足够证据时回到澄清节点，不能根据训练记忆补全课程事实。

### 步骤四：加入流式事件、取消与检查点

向前端发送命名事件，如 `phase_changed`、`text_delta`、`tool_started`、`citation`、`needs_confirmation` 和 `done`。断线、重连和重复事件用 sequence 去重。每次外部调用前保存检查点，恢复时核对副作用状态和配置版本。

### 步骤五：执行故障注入与岗位答辩

依次注入检索空结果、模型格式错误、MCP 断线、任务服务超时、重复确认和取消竞态。导出一次完整 trace，证明每个异常进入预期终态。答辩说明为何选择当前角色数量、如何保护学生数据、失败后由谁处理以及上线仍需哪些条件。

## 关键代码与配置

以下 reducer 展示程序如何验证主题与确认事件。实际项目应持久化事件，并用不可伪造令牌校验函数替代简单布尔值。

```python
def reduce_run(state, event):
    kind = event["type"]
    if kind == "cancel_requested":
        return {**state, "cancelled": True, "phase": "incomplete"}
    if kind == "lesson_saved":
        if event["course_id"] != state["course_id"]:
            raise ValueError("course_mismatch")
        return {**state, "topic_id": event["topic_id"], "phase": "plan"}
    if kind == "task_previewed":
        return {**state, "phase": "confirm", "action_hash": event["hash"]}
    if kind == "task_confirmed":
        if event["hash"] != state.get("action_hash"):
            raise ValueError("confirmation_mismatch")
        return {**state, "phase": "commit"}
    if kind == "task_committed":
        return {**state, "phase": "completed", "artifact_id": event["id"]}
    raise ValueError(f"unsupported_event:{kind}")
```

配置样例只列出非敏感项：模型最大调用 6 次、工具最大调用 10 次、运行截止 90 秒、确认有效期 10 分钟、知识 top_k 4。真实 API 密钥由运行环境注入，测试使用固定模拟客户端，不得把个人密钥交到项目仓库。

## 调试和常见故障

### 故障一：教学内容更新后仍追问旧知识点

- 现象：页面已经展示“工具参数校验”，系统却继续询问上一节“执行循环”的题目，引用也来自旧材料。
- 原因：教学内容与 active_topic 分两次非原子更新；问题生成器读取了缓存中的旧 topic，或并发流式任务晚到覆盖了新状态。
- 定位：按 run_id 比较 `lesson_saved`、`topic_changed` 和 `question_started` 的 sequence，核对生成请求携带的 course_id、topic_id 与材料引用。
- 修复：用同一事件原子保存内容和主题；生成前读取最新版本并携带 expected_version；丢弃旧 sequence 的迟到结果；加入主题一致性回归用例。

### 故障二：用户取消后任务仍被创建

- 现象：前端显示“已取消”，几秒后学习任务列表新增记录，审计日志出现提交成功。
- 原因：取消只停止流式展示，没有传播到服务端；提交工具开始前未检查取消标志，或超时重试绕过了检查点。
- 定位：重放取消、确认、commit_started 与 commit_finished 事件顺序，查询任务服务的幂等键和实际写入时间。
- 修复：取消写入共享运行状态；任何副作用前再次校验；若提交已发出则查询确定结果并如实告知用户，不能把未知状态显示成取消成功。

### 故障三：恢复运行重复消费旧确认

- 现象：服务重启后自动提交了此前预览的任务，而用户没有在恢复后的会话中确认。
- 原因：检查点只保存 `phase=commit`，没有保存确认令牌期限、动作摘要或用户会话绑定。
- 定位：检查恢复快照和令牌声明，确认恢复时间是否超过有效期、参数是否改变、用户会话是否仍一致。
- 修复：持久化完整确认元数据并在恢复时重新验证；令牌过期或配置版本改变则回到 confirm，展示当前参数供用户再次决定。

## 安全、成本与职业规范提示

对模型输入执行长度与类型限制，对外部资源按不可信数据处理，对工具按最小权限注册。学生档案只在完成学习任务所需范围内使用，日志脱敏并有保留期限。涉及学习评价或推荐的结果向用户说明依据和局限，教师能够人工纠正；系统不能把模型评分直接当作处分或资格决定。

成本预算在运行开始前写入状态，达到阈值进入 incomplete 并保留已完成产物。流式输出提升感知速度，但不能掩盖总时延；应分别记录首字时间和完成时间。上线前还需容量测试、备份恢复、依赖清单、漏洞修复流程和负责人值班安排，演示成功不等于生产就绪。

## 实训练习

1. 编写主题切换与迟到流事件测试，证明旧问题无法覆盖新课程状态。
2. 模拟提交请求成功但响应丢失，用幂等键恢复确定结果。
3. 构造知识证据不足和证据冲突场景，设计澄清、拒答与转教师策略。
4. 在 Agent 规划中注入未注册工具名，验证 Schema 与注册表双重拒绝。
5. 导出一次脱敏 trace，让同学在不知道实现细节时定位故障根因。
6. 用同一验收集比较单 Agent 与当前混合工作流，报告质量、P95 延迟和成本。
7. 制作上线前检查清单，覆盖权限、密钥、告警、回滚、数据删除和人工接管。

## 本项目小结

综合项目将执行循环、可靠工具、记忆、工作流、知识服务、MCP 与协作角色统一到一个可验收系统中。真正的交付标准是：用户知道系统正在做什么，知识结论有出处，状态变化与当前主题一致，高风险动作受人控制，取消和失败拥有诚实终态，工程团队能够从事件证据复现问题。这些能力比一次流畅对话更能体现 Agent 开发工程师的职业水平。
