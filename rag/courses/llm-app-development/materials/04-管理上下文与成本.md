# 项目4：管理会话上下文与 Token 成本

## 岗位情境

在线实训辅导页面把全部历史消息原样发送给模型。会话开始时响应迅速，二十轮后请求偶尔超过上下文限制；团队临时删除最早消息，又使模型忘记课程规则。账单记录只按请求数汇总，无法说明哪个课程、会话或功能消耗最多。你需要实现一个带预算的会话服务：稳定规则始终保留，历史按信息价值选择，摘要可追溯，响应中的实际用量回写成本台账。

本项目仍然是大模型应用层的会话管理，不实现长期记忆检索或 Agent 自主决策。Token 估算用于请求前控制，最终计量以服务响应的原生 `usage` 为准；不同模型的分词和多模态计费方式可能不同。

## 项目目标

- 能画出上下文窗口中固定指令、当前任务、近期对话、摘要和输出预留的预算分区。
- 能根据模型上限和产品配置计算输入预算，在发请求前拒绝不可能完成的组合。
- 能实现按完整消息裁剪和版本化摘要，避免截断半条 JSON、工具消息或用户问题。
- 能记录 prompt、completion、cached、reasoning 等可用用量字段及业务维度。
- 能用长会话样本验证规则不丢失、成本可解释、降级可观察。

## 项目产物与验收条件

产物是 `ContextBudget`、会话裁剪器、摘要记录和一份成本分析表。

- [ ] 输入模型上下文上限、输出预留、固定消息和历史后，输出最终消息数组与预算决策。
- [ ] 固定 system 规则、当前用户问题和必要成对消息不得被单独裁掉。
- [ ] 超预算时按“移除低价值历史→使用已验证摘要→降低输出或更换模型→拒绝”顺序处理。
- [ ] 台账记录 course、feature、session、model、usage、latency、cache 状态和 trace_id，不保存敏感正文。
- [ ] 验收证据包含三档长度测试、一次摘要前后事实核对、实际/估算偏差表和成本聚合结果。

## 任务分析

### 岗位任务、输入与输出

输入包括模型标识与已核验的上下文上限、最大输出 Token、固定消息、历史轮次、已批准摘要和产品预算；输出是有序消息、估算用量、预留量、采取的裁剪动作，调用后再补充真实用量与费用。岗位人员需要同时保护任务正确性、交互延迟和单位经济性，不能只追求塞入更多文本。

可复现实训准备 3、20、80 轮三个脱敏会话，其中埋入一条长期课程规则和三个需要保留的事实。使用确定性字符近似器先测试决策，再选择允许的模型执行一次可选实测，比较估算与返回 `usage`。每次摘要都保存来源消息 ID、摘要版本和事实检查结果。

## 核心知识

### 上下文预算不是最大输出参数

模型上下文通常容纳输入与生成输出，应用需要先预留输出，再决定可以发送多少输入。一个实用关系是：`输入预算 = 上下文上限 - 输出预留 - 安全余量`。`max_tokens` 或供应商对应参数限制生成上限，并不会自动压缩历史。还应为工具定义、多模态内容和供应商附加格式留出余量，不能把公开上限全部耗尽。

### 消息的结构完整性与价值

裁剪单位应是语义完整的消息组。system 规则、当前问题、与当前任务直接相关的近期轮次优先级最高；闲聊和已经被可靠摘要覆盖的旧轮次优先级较低。若存在 tool 请求与 tool 结果，它们必须成对保留或成对移除。简单从字符串头部切字符会破坏角色顺序、JSON 结构和因果关系。

### 摘要有损且必须可追溯

摘要不是原历史的等价压缩。摘要提示要区分事实、未决问题、用户偏好与已完成动作，禁止把建议写成已执行事实。生成后应检查关键实体和否定关系，保存覆盖的消息 ID 与摘要版本。当会话主题转移或摘要多次递归压缩时，错误会累积，必要时应回到原记录重新生成，而不是只摘要旧摘要。

### 估算、真实用量和缓存

请求前估算只能用于保护边界；OpenRouter 文档说明响应 usage 使用实际模型的原生 tokenizer 计数，并可能包含缓存、推理或多模态明细。台账应宽松接收未知新增字段，核心指标按 `prompt_tokens`、`completion_tokens` 和 `total_tokens` 归一化。缓存命中不意味着输入免费或无隐私影响，必须依据实际提供方规则核算。

## 工程实现步骤

1. 建立模型能力配置，记录上下文上限、默认输出预留、是否有本地 tokenizer 以及最后核验日期。
2. 给每条消息分配 ID、角色、创建时间、重要级别、是否敏感和关联任务；按轮次或调用关系组成不可拆分组。
3. 计算固定内容和当前问题的估算量。若它们已经超预算，直接提示缩小输入或选择更大上下文模型。
4. 从低优先级完整组开始移除，直到满足预算；有合格摘要时插入摘要消息，并记录替代的 ID 范围。
5. 请求体设置输出上限；响应后检查 `finish_reason=length`，不要把截断回答当完整成功。
6. 将估算、真实 usage、延迟、模型和业务标签写入追加式台账，密钥和正文不进入指标。
7. 按课程、功能、模型和日期聚合单位会话成本与 P95 延迟，识别异常长提示和重复调用。
8. 对三档会话运行回归，验证固定规则和事实问答；记录摘要造成的事实损失并调整策略。

## 关键代码与配置

下面预算对象只负责做决定，不调用模型，便于纯单元测试。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class ContextBudget:
    context_limit: int
    output_reserve: int
    safety_margin: int = 512

    @property
    def input_limit(self) -> int:
        value = self.context_limit - self.output_reserve - self.safety_margin
        if value <= 0:
            raise ValueError("输出预留与安全余量超过上下文上限")
        return value

def fits(estimated_input: int, budget: ContextBudget) -> bool:
    return estimated_input <= budget.input_limit
```

## 调试和常见故障

### 故障案例一：删除最早消息后课程规则失效

- **现象：** 长会话仍能请求成功，但模型开始用禁止的评分方式回答。
- **原因：** 裁剪器按数组头部删除消息，把稳定 system 规则与普通历史一并移除。
- **定位：** 输出最终消息的角色、ID 和长度摘要，比较短会话与长会话，确认 system ID 不再存在。
- **修复：** 将固定规则设为不可裁剪分区，只从有优先级的历史组中移除；添加长会话规则保持断言。

### 故障案例二：估算未超限却被上游拒绝

- **现象：** 本地显示尚余数百 Token，请求仍返回上下文过长；包含图片或工具定义时更常见。
- **原因：** 使用字符数除以固定常量估算，遗漏消息包装、工具 Schema、多模态和模型特定分词差异。
- **定位：** 对比估算与成功响应的真实 prompt_tokens，按输入类型计算偏差分布，检查安全余量是否过小。
- **修复：** 可用时采用对应 tokenizer；保留经数据校准的安全余量，对多模态和工具单独预算，边界附近主动降级。

### 故障案例三：摘要把“计划提交”写成“已经提交”

- **现象：** 后续回答声称学生已完成任务，但原记录只是表达意愿。
- **原因：** 摘要没有区分事实状态，且递归摘要多次放大了语义变化。
- **定位：** 通过摘要记录中的来源消息 ID 回放原文，核查时态、否定词和动作状态。
- **修复：** 使用事实/计划/未决问题分栏摘要，增加状态核验；超过递归次数时从原消息重新生成并人工抽查。

## 安全、成本与职业规范提示

会话历史可能包含个人信息、教学评价和内部规则。上下文变短不等于数据已经删除：原日志、摘要和供应商留存仍需纳入数据清单。成本台账用不可逆或受控标识关联会话，分析人员只获得必要维度。摘要前先去标识化，删除请求必须同时处理原消息与派生摘要。

成本优化不能牺牲关键事实或把未核验模型悄悄换入高影响场景。模型目录、价格和窗口会变化，课程不把具体数值写死为永久事实；运行配置需要来源与核验时间。报告同时呈现质量、延迟、Token 和金额，避免只用“请求次数下降”证明优化成功。

## 实训练习

1. 为 3、20、80 轮会话设置相同规则与事实，运行裁剪器并保存最终消息 ID、估算量和动作序列。
2. 故意把 system 放在普通历史中，复现规则丢失，再写测试保证它永远保留。
3. 生成一份结构化摘要，逐项核对事实、计划、否定关系和未决问题，记录来源消息 ID。
4. 以模拟 usage 写入十条台账，按 feature/model 聚合总量、单会话均值和 P95 延迟；证明日志无正文。
5. 若具备授权，执行一次真实调用比较估算与原生计数；否则使用教师提供响应样本。提交命令、输出、偏差解释和验收证据索引。

## 本项目小结

上下文管理是一项预算与信息价值的工程决策。输出预留、固定规则、消息组、摘要和安全余量需要显式建模；请求前估算保护边界，请求后原生 usage 支撑真实核算。可追溯摘要和三档长会话回归能避免“为了省 Token 忘掉任务”。下一项目会把图片和文件加入输入，并单独处理格式、体积、隐私与模型能力。
