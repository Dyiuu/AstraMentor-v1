# 项目7：实现可取消的流式对话体验

## 岗位情境

大模型答疑服务平均需要十几秒才显示完整文本，学生反复点击发送，产生重复请求。团队改为流式转发后又出现新问题：UTF-8 汉字被拆成乱码，用户点击停止只关闭了前端显示，上游仍继续生成并计费；流中途返回错误时页面永久停在“思考中”。你要交付一条从上游 SSE 到浏览器的受控流，定义事件、缓冲、取消、断线和非流式降级的完整状态机。

本项目优化应用服务交互，不讨论模型内部推理过程。界面可以展示“正在生成”，但不得伪造或暴露供应商未提供的思维链。流式输出改善首段可见时间，不必然缩短总生成时间。

## 项目目标

- 能解释 SSE 帧、增量内容、结束标记与流内错误的差别。
- 能增量解码 UTF-8，并在服务端归一化为稳定的 `meta/delta/usage/error/done` 事件。
- 能让浏览器取消、客户端断线与后端截止时间共同关闭上游连接。
- 能防止重复提交，支持超时、有限并发和模型不支持流式时的显式降级。
- 能测量首事件、首文本、总时长、取消耗时和生成用量，形成体验验收证据。

## 项目产物与验收条件

产物包括流式代理、事件契约、前端消费示例、取消通道和自动化测试。输入为已校验消息、取消信号和模拟上游字节流；输出为有唯一终态的应用 SSE 事件序列；验收证据按下列条目收集。

- [ ] 输入一次对话请求，浏览器按序收到一个 meta、若干 delta、可选 usage，最后恰好一个 done。
- [ ] UTF-8 跨块、空注释帧和 `[DONE]` 都能正确处理，内容不重复也不丢字。
- [ ] 用户取消或浏览器断开后，上游连接在可测上限内关闭，界面进入 cancelled 而不是 success。
- [ ] 流内错误会保留已显示内容并给出可重试提示，loading 状态一定结束。
- [ ] 验收证据包含五种模拟流、事件序列断言、网络面板或日志、四项延迟指标和调用次数。

## 任务分析

### 岗位任务、输入与输出

输入是已校验消息、模型参数、请求 ID、取消信号和上游字节流；输出是应用自有的 SSE 事件序列及最终状态。岗位任务包含两个状态机：后端负责连接、解析、转发和释放，前端负责 idle、connecting、streaming、completed、cancelled、failed。只有收到正常结束或已验证的完成原因才算 completed。

可复现实训用异步生成器构造正常小块、汉字跨字节、心跳注释、流内错误、延迟首块与永不结束六种流。所有延迟使用可控短时间，测试记录事件顺序和资源关闭标志。可选真实调用只用于测首文本时间，不能代替故障桩验收。

## 核心知识

### SSE 与增量语义

OpenRouter 流式请求设置 `stream: true`，响应按 Server-Sent Events 传递，数据块中的 choice 使用 `delta` 而非完整 `message`。流可能包含注释心跳，应忽略而不是解析成 JSON；最终 `[DONE]` 表示传输结束，usage 可能只在接近结束的单独块出现。HTTP 200 只说明流已建立，后续仍可能发生上游错误，所以错误必须进入事件协议。

### 字节、文本、事件三层缓冲

网络块不等于 UTF-8 字符边界，也不等于一条 SSE 事件。一段中文字符可能跨两个字节块，一条 `data:` 也可能分段到达。正确实现先用增量解码器把字节变成文本，再以空行识别完整 SSE 事件，最后解析 data JSON。逐块直接 `.decode()` 或假定每块一行都会在压力下产生乱码与丢帧。

### 取消是端到端资源释放

浏览器的 AbortController 只能终止本地 fetch；服务端还要检测断开或接受取消标识，并关闭 `httpx` 上游流。应用设置连接超时、首块超时、总截止时间和空闲超时，分别处理不同卡顿。取消不是错误成功混合态：已显示文本可保留，但不能写成完整回答，也不应自动把半截内容加入下一轮历史。

### 体验与背压

每个 token 触发一次 React 更新会造成抖动，可按 30–80 毫秒批量刷新，同时保持原始事件顺序。服务端要限制每个用户并发和缓冲上限；慢客户端不能无限占用内存。指标至少包含 time-to-first-event、time-to-first-text、total-duration 和 cancel-to-close，且分别标记模型、网络与渲染阶段。

## 工程实现步骤

1. 定义版本化事件：meta 携带 trace_id/model，delta 只含文本片段，usage 含计量，error 含公开错误码，done 含终态。
2. 上游请求设置 `stream: true`、分层超时和最大输出；用 `httpx.AsyncClient.stream` 保持连接上下文。
3. 增量读取字节，使用 UTF-8 incremental decoder；按 SSE 空行聚合事件，忽略以冒号开头的注释。
4. 解析每个 data；遇 `[DONE]` 正常收尾，累加 delta 但保留原序，usage 只记录不渲染为正文。
5. 捕获流中结构化 error、网络错误和协议错误，发一个 error 后发 failed done；不得继续假装完成。
6. 前端为每个提交创建 AbortController，发送期间禁用重复提交；小批量合并 delta，done 时清理定时器。
7. 后端在客户端断开、截止时间或取消时关闭上游迭代器，并在 finally 释放连接、并发令牌和指标计时器。
8. 运行六种模拟流，断言终态唯一、资源关闭、无乱码和无空助手消息；记录四项体验指标。

## 关键代码与配置

应用事件不要直接暴露供应商原始块，便于前端稳定消费。

```python
import json

def sse(event: str, payload: dict) -> bytes:
    data = json.dumps(payload, ensure_ascii=False, separators=(",", ":"))
    return f"event: {event}\ndata: {data}\n\n".encode("utf-8")

async def forward(source):
    yield sse("meta", {"stream_version": 1})
    try:
        async for text in source:
            if text:
                yield sse("delta", {"text": text})
        yield sse("done", {"status": "completed"})
    except Exception:
        yield sse("error", {"code": "upstream_stream_failed"})
        yield sse("done", {"status": "failed"})
```

```javascript
const controller = new AbortController();
const response = await fetch("/api/chat/stream", {
  method: "POST",
  body: JSON.stringify(payload),
  signal: controller.signal,
  headers: {"Content-Type": "application/json"}
});
// “停止生成”按钮调用 controller.abort()；服务端仍须关闭上游连接。
```

## 调试和常见故障

### 故障案例一：中文偶尔显示替换字符

- **现象：** 正常短回答无问题，限速或代理分块后出现 `�`，重新请求位置又不同。
- **原因：** 代码对每个网络字节块单独 `decode("utf-8")`，恰好把多字节汉字拆开。
- **定位：** 用固定汉字编码后人为按每个字节切块，运行解析器；检查是否在 SSE 成帧前直接解码和 JSON 解析。
- **修复：** 使用增量 UTF-8 解码器并在结束时 flush，再按空行组装完整事件；加入跨字节回归流。

### 故障案例二：点击停止后上游仍产生用量

- **现象：** 页面立即停止，但服务端数十秒后才记录 done，usage 接近完整回答。
- **原因：** 前端只终止读取，后端没有感知断开，异步任务仍消费上游流。
- **定位：** 对照浏览器 abort 时间、后端 disconnect 日志、上游连接关闭标志和最终 usage。
- **修复：** 将取消信号端到端传播，在 disconnect/finally 中关闭响应迭代器；用 cancel-to-close 指标设置验收上限。

### 故障案例三：流内错误导致界面一直加载

- **现象：** 已显示半段文字后不再更新，发送按钮持续禁用，HTTP 状态仍是 200。
- **原因：** 前端只处理 delta 和 `[DONE]`，忽略流中 error；后端异常路径也未发终态。
- **定位：** 注入“两个 delta 后 error”的模拟流，记录前端状态转换，确认没有 failed 或清理动作。
- **修复：** 统一发 error 加 failed done；前端用 finally 清理控制器和计时器，保留半段并标识未完成。

## 安全、成本与职业规范提示

流式内容在完整输出校验前已经展示。涉及高风险或必须整体审核的场景，应先缓冲、校验后再显示，或对增量执行可接受的前置/后置控制。服务端不能把上游原始错误、请求头或提示回显给浏览器。取消接口需要绑定当前用户与请求，防止他人猜测 ID 终止会话。

取消必须真正释放上游资源才能控制成本；并发限制按用户、会话和全局共同实施。流式指标与文本日志分离，正文默认不采集。产品文案要准确：显示“正在生成”而不是“正在验证事实”，已取消或失败内容不能自动当作已确认的学习记录。

2. 复现逐块 decode 的乱码，改用增量解码并建立固定测试。

## 本项目小结

流式体验是一条端到端协议，而不是简单打开 `stream` 参数。字节增量解码、SSE 成帧、应用事件、双端状态机和资源释放必须协同；首文本更快不代表总时间更短。通过故障流和取消指标，团队能证明交互改善没有以泄露、重复计费或悬挂任务为代价。最后一个项目将把客户端、提示、结构化、多模态、工具和流式能力组合为可配置业务应用。
