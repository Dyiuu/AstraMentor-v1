# 项目5：开发可校验的图文多模态应用

## 岗位情境

实训教师希望上传设备仪表照片，由模型提取读数并给出“需要人工复核”的提示。原型只检查扩展名，把用户上传的任意文件编码为 Data URL；一张超大图片使请求延迟显著增加，旋转方向错误又导致读数识别偏差。更换文本模型后，接口仍返回成功，但回答声称“看不到图片”。你要构建从上传校验、标准化、能力检查、模型请求到结果复核的图文处理功能。

本项目以低风险教学图片为样例。模型视觉结果不能替代设备检定或安全操作，且课程不延伸到计算机视觉模型训练、OCR 算法训练或多步骤 Agent。

## 项目目标

- 能依据真实文件内容、像素、尺寸和业务授权验证图片，而非只看文件名。
- 能在不泄露本地路径的前提下构造兼容接口的文本与 `image_url` 内容数组。
- 能查询并记录模型输入模态能力，对不支持图片的模型拒绝或显式降级。
- 能设计图像预处理、输出 Schema、置信边界和人工复核流程。
- 能用正常、旋转、模糊、超限和伪装文件完成离线可复现验收。

## 项目产物与验收条件

产物是上传校验器、图片标准化函数、多模态请求构造器和仪表读数结果对象。

- [ ] 输入 JPEG/PNG 教学图片与任务文字，输出规范化图片元数据和结构化读数结果。
- [ ] 非图片、解码失败、像素或字节超限在模型请求前拒绝，临时文件按策略清理。
- [ ] 请求记录图片哈希、宽高、处理动作、模型能力和 trace_id，不记录 Data URL 正文。
- [ ] 无法清楚识别时输出 `needs_review=true` 与原因，不能编造精确读数。
- [ ] 验收证据包括五类本地样本、校验测试、前后尺寸统计、模拟模型结果和人工核对表。

## 任务分析

### 岗位任务、输入与输出

输入包括获授权的图片字节、声明 MIME、业务场景、问题文本、模型能力信息和大小限制；输出包括标准化图片、内容哈希、宽高、格式、预处理记录，以及通过 Schema 校验的读数或拒绝原因。上传处理与模型推理是两道独立边界：只有通过解码和资源限制的图片才能进入请求，只有经过业务复核的模型结果才能进入教师页面。

可复现实训使用自行制作的仪表卡片或公开许可的非敏感样图，创建正常、EXIF 旋转、强模糊、超大像素和将文本改名为 `.jpg` 五类样本。图片处理测试完全离线；模型响应用固定桩返回“明确读数”和“无法判断”两种 JSON，验收不依赖付费服务。

## 核心知识

### 多模态消息与能力差异

OpenAI 兼容聊天结构通常把用户消息 `content` 从字符串变为内容项数组，文本项与 `image_url` 项按顺序出现；URL 可指向受控 HTTPS 资源，也可使用带 MIME 的 Data URL。不同模型支持的输入模态、图片数量、格式和参数不同。调用前要依据模型目录或能力配置验证图像输入，不能从“兼容聊天接口”推断它一定能看图。

### 文件安全与资源边界

扩展名和浏览器上报 MIME 都可以伪造。服务端应限制上传字节、尝试用成熟图像库解码、限制像素总量和帧数，并重新编码为允许格式。像素炸弹可能文件很小却消耗大量内存；动态图或附带元数据也要按业务需要处理。临时文件使用随机内部名称，绝不能把用户文件名直接作为路径。

### 标准化与可复核输出

EXIF 方向会影响模型看到的内容，应在去除元数据前先应用方向变换。根据实际读数需求缩放而不是盲目压成缩略图，保留原始哈希与转换参数。输出模式至少包含 `value`、`unit`、`visible_evidence`、`needs_review` 和 `review_reason`。模型描述的置信度不是统计校准概率，只能作为流程信号；模糊、遮挡、刻度不完整时应强制人工复核。

## 工程实现步骤

1. 写出允许格式、最大字节、最大像素、最长边、是否允许动画和数据保留时间，获得业务负责人确认。
2. 读取有限字节并计算 SHA-256；使用 Pillow 打开、`verify` 后重新打开，捕获解码错误和炸弹警告。
3. 应用 EXIF 方向，转换到允许色彩模式，按最长边等比例缩放，重新编码为 JPEG 或 PNG 并移除不需要的元数据。
4. 对模型能力做配置检查；不支持图片时返回 `unsupported_modality`，若产品允许，可提示用户改用人工录入，而不是让文本模型猜测。
5. 构造一条 user 消息，先放任务文字再放图片；控制任务只要求读取可见信息，并定义无法识别行为。
6. 以结构化模式接收结果，本地验证单位枚举、值范围和证据文字；必要时与人工双录结果比较。
7. 日志只写图片哈希前缀、尺寸、动作、模型和用量；Data URL、原图和个人信息不进入普通日志。
8. 跑五类样本和两个响应桩，保存处理统计、错误类型、人工核对结果和复现命令。

## 关键代码与配置

请求构造只接收已经通过校验并重新编码的字节。

```python
import base64

def image_message(prompt: str, mime: str, clean_bytes: bytes) -> dict:
    if mime not in {"image/jpeg", "image/png"}:
        raise ValueError("图片格式不在允许列表")
    encoded = base64.b64encode(clean_bytes).decode("ascii")
    return {
        "role": "user",
        "content": [
            {"type": "text", "text": prompt},
            {"type": "image_url", "image_url": {
                "url": f"data:{mime};base64,{encoded}"}},
        ],
    }
```

```json
{

  "needs_review": true,
  "review_reason": "图片有反光，刻度边界不够清晰"
}
```

## 调试和常见故障

### 故障案例一：后缀为 JPG 的文件导致解码异常

- **现象：** 浏览器允许上传，后端图像库报无法识别，旧实现却已把文件发往模型。
- **原因：** 只检查文件名和客户端 MIME，实际内容是一段文本或损坏字节。
- **定位：** 用隔离环境保存样本哈希，检查解码步骤是否发生在网络调用前，确认请求计数本应为零。
- **修复：** 服务端限定读取量、真实解码和重新编码；解码失败返回统一错误，不保留或转发原字节。

### 故障案例二：仪表读数方向颠倒

- **现象：** 人眼在文件管理器中看到图片正向，发送后的预览与模型结果却旋转 90 度。
- **原因：** 原像素依赖 EXIF 方向显示，处理程序删除元数据前没有应用方向变换。
- **定位：** 分别记录原始像素宽高、EXIF 方向和标准化预览，比较客户端显示与实际编码内容。
- **修复：** 解码后先执行 EXIF transpose，再缩放和去元数据；加入带方向标签的固定回归图。

### 故障案例三：文本模型声称分析了图片

- **现象：** 接口返回流畅读数，但模型目录未声明图像输入，答案与问题中的暗示一致。
- **原因：** 应用未做模态能力检查，提供方忽略图片项或只处理文字。
- **定位：** 记录实际模型和支持参数，用没有任何读数提示的控制图片测试，确认结果来自文字猜测。
- **修复：** 调用前强制验证输入模态；不支持时拒绝并给出人工录入路径，结果页展示实际使用模型与能力状态。

## 安全、成本与职业规范提示

图片可能包含人脸、工牌、地理位置和设备编号。采集前明确目的和授权，尽量在上传前裁去无关区域；EXIF 与原文件按保留政策处理。第三方 URL 可能带来服务端请求伪造风险，本项目优先使用受控上传，不允许模型服务任意拉取用户给出的内网地址。恶意图片解析应在更新及时、资源受限的环境中进行。

图像会显著影响请求体、延迟和计量，需按模型实际 usage 统计。缩放必须同时验证任务质量，不能只以费用下降为成功。仪表读数涉及设备安全时，模型输出只用于辅助，必须由具备资格的人员核验；报告要展示模糊和遮挡失败案例，不能挑选单张成功图片夸大能力。

## 实训练习

1. 制作五类非敏感图片样本，记录来源许可、哈希、字节、像素、方向和预期处理结果。
2. 实现上传校验与标准化，证明伪装文件和超限像素不会触发模型请求。
3. 用响应桩验证明确读数和无法识别两条路径，检查 `needs_review` 与单位范围。
4. 对同一图片生成原始、正确旋转和过度压缩版本，比较人工可读性与模拟结果，给出最长边建议。
5. 提交本地复现脚本、标准化预览、处理统计和人工核对表；所有证据不得包含真实学生或内部设备信息。

## 本项目小结

多模态应用的工程链条从文件进入服务时就开始，而不是从提示词开始。真实解码、资源限制、方向标准化和模态能力检查保证输入可信；结构化结果、可见证据与人工复核控制输出风险。哈希和处理记录让同一图片可复现但不在日志复制敏感内容。下一项目会让模型提出受控函数请求，并明确模型建议和应用执行的界线。
