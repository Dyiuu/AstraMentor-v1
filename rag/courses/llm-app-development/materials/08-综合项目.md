# 项目8：交付可配置的大模型业务应用

## 岗位情境

学院要求在两周内演示“实训记录质检助手”：教师提交文本，可选附一张操作截图，系统输出结构化问题清单；对于明确的课程编号可查询只读课程表；回答需要流式呈现并允许停止。以往团队把多个课堂示例复制进一个路由，配置、错误和日志互不一致，任何模型能力变化都会导致整页失败。你作为项目负责人，要把前七个项目的能力组合成边界清晰、可测试、可演示的 MVP。

综合项目仍是大模型业务应用：最多一次工具请求与一次总结，不引入自主规划、长期记忆、完整 RAG 或多智能体。成功标准是工程证据和失败可控，而不是演示时碰巧得到一段好文字。

## 项目目标

- 能把业务需求转换为功能、非功能、数据和模型能力四类验收项。
- 能以端口/适配器方式组合客户端、提示、Schema、预算、多模态、只读工具和流式传输。
- 能在启动与请求阶段检查能力，并对不支持结构化、图片、工具或流式的情况选择拒绝或批准的降级。
- 能建立从输入验证到响应完成的 trace、用量和错误分类，不记录敏感正文。
- 能用自动化测试、演示脚本、运行手册和验收矩阵交付可重复的职业项目。

## 项目产物与验收条件

最终产物为一个可运行 API 服务、配置示例、测试套件、演示数据和交付文档。输入为脱敏实训记录、可选教学图片、课程查询参数和服务配置；输出为结构化质检报告、流式状态和审计摘要；验收证据由测试、演示与故障演练共同构成。

- [ ] 纯文本质检返回符合 `QualityReport` 的对象，并以安全的流式事件逐步展示摘要。
- [ ] 合法图片通过标准化后进入支持视觉的模型；无视觉能力时按产品策略拒绝且说明原因。
- [ ] 课程查询只调用白名单只读工具，requested 与 executed 事件一致，越权时实际调用为零。
- [ ] 每次请求有预算决策、trace_id、模板版本、模型、实际 usage、终态和脱敏错误。
- [ ] 验收证据包含一键启动说明、至少十二条测试、四个演示场景、失败演练、接口契约和回滚配置。

## 任务分析

### 岗位任务、输入与输出

输入是脱敏实训记录、可选教学图片、请求者可访问课程集合以及运行配置；输出是 `QualityReport`、可选课程表证据、流式状态与审计摘要。系统先验证文件和文本，再计算上下文预算，选择满足所需能力的模型，渲染版本化提示，执行单次推理；只有出现合法只读工具请求才进入批准与执行，然后生成最终报告。

可复现实训在本地用模拟模型与内存课程表运行，不需要真实密钥。十二条测试覆盖四条主路径和八条失败路径；演示数据固定哈希。可选真实兼容接口验收放在单独配置下，并确保没有真实学生记录。验收者按文档在新终端完成启动、请求、取消和错误演练。

## 核心知识

### 组合能力而不是复制代码

应用层编排业务顺序，传输适配器负责 HTTP，模板仓库负责版本，模式验证器负责数据，媒体服务负责图片，工具网关负责受控执行，流式协议负责交互。每个组件都有输入、输出和可替换的测试替身。把它们全部写进控制器会让异常处理分叉，难以证明某条路径是否跳过验证。

### 能力矩阵与降级决策

配置模型不等于它支持每种功能。启动时加载模型能力快照，请求时根据是否含图片、是否必须 strict Schema、是否允许工具和是否要求流式计算 `required_capabilities`。降级必须由产品风险事先批准：例如流式不可用可回退整包响应，视觉不可用则不能把图片任务交给文本模型猜测，严格结构不可用时高风险导入直接拒绝。

### 失败原子性与终态

输入、模型调用和只读工具分别可能失败。报告只有在 Schema、事实边界和必要工具结果都通过后才标记 completed；取消和流中错误保留可显示草稿，但不写入正式报告。trace_id 串联上传、模型和工具事件，状态不能后退或同时出现两个终态。由于本项目无写入工具，失败无需补偿业务副作用。

### 可交付证据

职业项目需要证明他人能够运行。测试报告只能证明已声明场景，仍要配套接口契约、环境变量清单、模型能力核验、演示输入、预期输出、故障演练和已知限制。README 不放真实密钥或内部 URL；配置示例用占位符。版本至少覆盖应用、提示、Schema 和课程材料。

## 工程实现步骤

1. 写用户故事与非目标，建立十二条验收用例；明确高影响数据不进入 MVP，工具仅查询公开课程表。
2. 画依赖方向，让业务服务依赖 `ModelPort`、`PromptStore`、`MediaPort`、`ToolRegistry` 接口，而不是具体 HTTP 实现。
3. 定义 `QualityReport` 和错误协议；把模板版本、Schema 版本及必需模型能力加入请求上下文。
4. 实现输入流水线：文本长度/敏感字段检查，图片解码/方向/像素处理，上下文预算计算。
5. 执行能力选择与单次模型调用；结构结果在本地验证。合法工具请求按白名单、参数与权限执行，再进行一次最终总结。
6. 通过应用 SSE 转发 meta、delta、usage、error、done；取消时关闭模型流，正式报告只在 completed 后持久化。
7. 使用模型桩、媒体样本和内存工具执行十二条测试，故意注入 401、Schema 错误、视觉不支持、越权和流中断。
8. 编写启动、健康检查、演示、排错和回滚手册；让未参与开发的同伴依文档完成验收并记录差异。

## 关键代码与配置

能力决策保持纯函数，便于测试每种组合。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Need:
    vision: bool = False
    strict_json: bool = True
    tools: bool = False
    streaming: bool = True

def missing(need: Need, available: set[str]) -> set[str]:
    required = {name for name, enabled in vars(need).items() if enabled}
    return required - available

def assert_capable(need: Need, available: set[str]) -> None:
    absent = missing(need, available)
    if absent:
        raise ValueError(f"模型缺少必要能力: {','.join(sorted(absent))}")
```

## 调试和常见故障

### 故障案例一：图片请求切到备用文本模型后出现虚构结果

- **现象：** 主模型限流触发 fallback，接口仍 completed，但报告描述了图片中不存在的按钮。
- **原因：** 路由只按可用性选择备用模型，没有把 vision 列为本请求必要能力。
- **定位：** 按 trace_id 查看 required_capabilities、实际模型与模型能力快照，复跑控制图确认备用模型未接收视觉。
- **修复：** fallback 候选先经过能力过滤；无合格候选则返回 `unsupported_modality`，不得降级为猜测。

### 故障案例二：工具失败后仍保存正式报告

- **现象：** 课程表查询超时，最终报告却标记 completed，并写有模型根据旧上下文猜出的上课时间。
- **原因：** 控制器在首次模型输出后就创建报告，工具结果不是完成条件。
- **定位：** 排列状态事件，发现 persisted 出现在 tool failed 之前；检查完成谓词没有必要证据条件。
- **修复：** 只有 Schema 有效且所有必需工具 executed 后才能提交报告；失败保留草稿并给出重试入口。

### 故障案例三：模拟测试通过但新同伴无法启动

- **现象：** 开发机测试全绿，新环境启动时报缺少模型配置，文档只写“正常运行项目”。
- **原因：** 测试注入了默认值，运行手册没有列出变量语义、安装命令和健康检查。
- **定位：** 在干净环境按文档逐行执行，比较实际读取的变量与 `.env.example`，记录第一个不可推断步骤。
- **修复：** 所有必需配置启动即校验；补充一键测试、模拟模式、预期健康响应和常见错误，重新做盲验。

## 安全、成本与职业规范提示

综合应用只处理获得授权的脱敏教学数据。图片、提示、工具结果和报告是同一数据链的派生物，访问与删除应保持一致。外部模型、日志和演示环境都要纳入数据流图。工具权限由认证上下文提供，结构化输出仍需本地校验；任何异常都不能把密钥、内部响应或堆栈发送给浏览器。

报告记录真实 usage、延迟和取消结果，以单位合格报告而非单位请求衡量成本。模型与提供方可替换，但必须重新跑能力和质量验收。演示人员必须说明这是 MVP、只读工具和人工复核边界，不能把流畅界面等同于事实可靠或生产安全。

## 实训练习

1. 完成十二条用例矩阵，至少包括纯文本、图文、合法工具、取消，以及八种配置/协议/权限失败。
2. 实现纯能力决策并覆盖所有组合，证明 fallback 不会丢失必要能力。
3. 用模拟模型跑一条完整请求，导出 trace 时间线、预算动作、模板版本、Schema 结果、工具状态和 usage。
4. 注入工具超时和流中断，证明正式报告没有提交、终态唯一、资源释放。
5. 邀请同伴在新终端按手册启动模拟模式并完成四个演示；把其遇到的问题修入手册，提交签收记录。

## 本项目小结

综合项目把七项能力组合为一个可证明的业务闭环：可靠客户端承接外部接口，版本化提示管理意图，Schema 与证据控制数据，预算约束上下文，多模态治理文件，工具网关执行只读查询，SSE 状态机改善交互。能力矩阵和失败原子性确保替换模型时不会悄悄降低质量。完成后，学生已具备交付单次模型调用类应用服务的岗位基础，可进入 RAG 知识检索工程课程。
