# 项目1：接入可替换的大模型服务

## 岗位情境

某职业培训平台准备把“课程问答摘要”接入大模型。试验代码能够在开发者电脑上返回一句话，却把密钥写在脚本里、没有超时、只会读取成功响应。更换兼容服务后，地址被重复拼接为两个 `chat/completions`，线上请求全部变成 404。你作为大模型应用开发工程师，需要交付一个可复用客户端，使业务代码只关心消息和结果，不感知供应商差异，并让运维人员能依据请求标识定位故障。

本项目只处理一次模型请求的工程封装，不实现自主循环、知识检索或多智能体编排。学生应在自己的测试账户或模拟服务中操作，任何示例值都不是可用密钥。

## 项目目标

- 能说明完整端点、模型标识、消息数组和鉴权头各自的职责。
- 能用环境变量装配 OpenAI 兼容客户端，并在启动时进行配置校验。
- 能区分连接、读取、HTTP 状态、协议结构和模型结束原因五类结果。
- 能为超时、限流和服务端故障制定有上限的重试策略，同时记录可关联的请求 ID。
- 能用模拟传输复现成功、超时和错误响应，不依赖真实付费调用完成验收。

## 项目产物与验收条件

项目产物是 `ModelClient`、配置示例、三个自动化检查和一份运行记录。

- [ ] 输入一组 `system/user` 消息后，输出统一的 `ModelResult(text, model, finish_reason, usage)`。
- [ ] 缺少密钥、模型或端点时，程序在发请求前给出不泄露配置值的中文错误。
- [ ] 401 不重试；429、连接失败和部分 5xx 最多重试两次，并采用递增等待。
- [ ] 日志包含本地 `trace_id`、HTTP 状态和上游请求标识，不包含 Authorization 内容。
- [ ] 验收证据包含测试命令、三种场景的终端输出截图或文本记录，以及一次配置清单审阅。

## 任务分析

### 岗位任务、输入与输出

岗位任务是把不稳定的外部推理接口变成边界清晰的内部服务。输入包括完整 HTTPS 端点、模型 ID、环境中的访问凭据、消息列表、最大输出量和超时策略；输出包括模型文本、归一化结束原因、用量数据或可分类异常。调用前校验解决“错误请求进入网络”的问题，调用后校验解决“HTTP 200 但响应形状不合约”的问题。

可复现实训使用 `httpx.MockTransport` 返回固定 JSON。先以成功样本建立基线，再替换为 401、429 和读取超时；每次运行保存 `pytest -q` 的退出码与日志。真实接口只用于教师允许的可选检查，不能成为合格的唯一条件。

## 核心知识

### 兼容不等于地址可以任意拼接

OpenAI 兼容通常指请求中的 `model`、`messages`、可选参数以及响应 `choices` 形状相近，不表示所有厂商拥有同一根路径或支持全部参数。配置应明确约定保存“完整聊天端点”还是“API 根地址”，只能选择一种。本项目保存完整端点，例如 `https://openrouter.ai/api/v1/chat/completions`，客户端不得再次追加路径。模型名称也作为运行配置，因为账户可见模型与参数能力会变化。

### 消息协议与结束原因

消息角色表达不同来源的指令和上下文。应用必须保留消息顺序，并在送出前限制单条和总长度。非流式成功响应通常从 `choices[0].message.content` 取文本；数组为空、内容为空或类型错误都属于协议异常。`finish_reason=stop` 表示正常停止，`length` 往往提示输出预算不足，`tool_calls` 则表示模型提出工具请求而不是最终答案。业务不能把所有 HTTP 200 都当成功文本。

### 超时、重试与可观测性

HTTPX 区分连接、读取、写入和连接池超时。职业项目至少显式设置连接与读取上限。重试只面向暂态故障，并设置次数、总时长和随机抖动；认证失败、参数错误及确定性的协议错误不应重试。模型生成可能已经发生计费，因此不能把任意超时请求视为绝对未执行。为每次业务调用生成 `trace_id`，保留上游响应头中的请求标识，能让调用方、网关和供应商日志建立关联。

## 工程实现步骤

1. 创建独立虚拟环境，安装项目锁定版本的 `httpx` 与测试工具；在 `.env.example` 只写变量名和占位符。
2. 定义不可变配置对象，读取 `ASTRA_API_ENDPOINT`、`ASTRA_MODEL_NAME`、`ASTRA_API_KEY`，校验 HTTPS、非空模型和合理超时。
3. 构造固定请求头；日志过滤器对 `authorization`、`api_key`、`token` 等键统一脱敏。
4. 编写 `complete(messages, max_tokens)`，对输入类型和数量先校验，再发送 POST。
5. 依据状态码分类：401/403 为配置或权限，429 为限流，5xx 为上游可用性；解析 JSON 前先保留状态和请求 ID。
6. 对响应执行形状校验，生成统一结果对象；未知新增字段忽略，关键字段缺失则失败。
7. 注入模拟传输，分别验证成功、认证失败、限流后成功和畸形 JSON。固定随机种子或取消真实等待，使测试快速稳定。
8. 用验收清单审阅日志与异常消息，确认任何路径都不会打印密钥或完整敏感提示。

## 关键代码与配置

下面代码强调“完整端点”和响应边界；生产实现还应注入重试策略与结构化日志。

```python
import os, httpx

ENDPOINT = os.environ["ASTRA_API_ENDPOINT"]
MODEL = os.environ["ASTRA_MODEL_NAME"]
KEY = os.environ["ASTRA_API_KEY"]

def complete(messages: list[dict]) -> str:
    timeout = httpx.Timeout(45.0, connect=5.0)
    headers = {"Authorization": f"Bearer {KEY}"}
    body = {"model": MODEL, "messages": messages, "max_tokens": 600}
    with httpx.Client(timeout=timeout) as client:
        response = client.post(ENDPOINT, headers=headers, json=body)
    response.raise_for_status()
    data = response.json()
    choices = data.get("choices") or []
    if not choices or not isinstance(choices[0].get("message"), dict):
        raise ValueError("模型响应缺少 choices[0].message")
    return choices[0]["message"].get("content") or ""
```

```dotenv
ASTRA_API_ENDPOINT=https://openrouter.ai/api/v1/chat/completions
ASTRA_MODEL_NAME=YOUR_COMPATIBLE_MODEL_ID
ASTRA_API_KEY=YOUR_API_KEY
```

## 调试和常见故障

### 故障案例一：完整端点被重复追加

- **现象：** 日志显示 POST 地址以 `/chat/completions/chat/completions` 结尾，上游返回 404。
- **原因：** 环境变量已经保存完整端点，初始化代码仍把它当作根地址追加固定路径。
- **定位：** 在脱敏日志中记录最终 URL 的 scheme、host、path，并与接口契约逐段对照；不要记录查询中的凭据。
- **修复：** 明确配置语义，本项目始终直接请求完整端点；增加测试断言最终 path 只出现一次目标资源。

### 故障案例二：读取超时触发无上限重试

- **现象：** 一个请求长时间占用工作线程，日志持续出现同一业务调用，费用和延迟不可预测。
- **原因：** 只有默认超时且 `while True` 捕获所有异常，没有最大次数和总时间预算。
- **定位：** 用模拟传输连续抛出 `ReadTimeout`，统计尝试次数、间隔及单次 trace_id；检查是否错误捕获 401。
- **修复：** 将重试限制为可判定的暂态异常，最多两次，计算退避并在总截止时间到达后返回可恢复错误。

### 故障案例三：HTTP 200 却显示空回答

- **现象：** 页面没有报错也没有文字，原始 JSON 中 `finish_reason` 为 `tool_calls`。
- **原因：** 客户端只读取 `message.content`，忽视消息可能携带工具请求或内容过滤结果。
- **定位：** 保存脱敏后的响应结构摘要，检查 choices 数量、finish_reason、content 类型和 tool_calls 是否存在。
- **修复：** 以联合类型归一化响应；当前项目对工具请求返回明确状态，到项目六再执行单轮工具协议。

## 安全、成本与职业规范提示

密钥只存在于服务端环境或密钥管理系统，不进入浏览器、仓库、截图和异常堆栈。日志应记录字段存在性而不是字段值。学生使用共享账户时必须设置预算与速率上限，真实调用前确认数据是否允许发送到外部处理方。提示中若包含学员姓名、成绩或联系方式，应先去标识化并遵守机构的数据授权和留存规则。

重试可能造成重复计费或重复生成，必须监控 `usage` 与请求次数。兼容层会归一化很多字段，但开发者仍需验证所选模型是否支持 `max_tokens`、结构化输出或工具；不支持时要明确降级，不能默默声称功能已生效。故障报告只陈述可验证事实，区分本地配置、网络、兼容网关与模型提供方责任边界。

## 实训练习

1. 用 `MockTransport` 构造正常响应，断言输入消息顺序不变、结果文本正确且日志不含 `YOUR_API_KEY`。

## 本项目小结

可靠接入的关键不是“成功请求一次”，而是把外部不确定性收敛为稳定内部契约。完整端点、模型能力、消息顺序、超时、状态码、响应形状和结束原因都必须被显式处理。通过配置外置、错误分类、有限重试、请求关联和模拟测试，业务团队才能安全复用这个模型客户端。下一项目将在此客户端之上管理提示模板和版本，不改变底层传输职责。
