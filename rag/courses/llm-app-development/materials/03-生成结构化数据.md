# 项目3：用 JSON Schema 生成可验证的结构化数据

## 岗位情境

学校就业中心希望把企业发布的岗位描述转换为统一数据，包括岗位名称、技能列表、学历要求和证据句。旧版程序要求模型“只返回 JSON”，随后直接 `json.loads`；有时出现 Markdown 围栏，有时技能字段从数组变成字符串，更严重的是模型补出了原文没有的薪资。下游导入程序因此中断或写入错误信息。你的任务是交付一个结构化提取接口，用模式约束、应用校验、有限修复和证据核对把风险挡在数据边界。

本项目处理一次模型调用的结构化结果，不把多轮自动重试扩展为自主 Agent。某些兼容模型不支持严格 JSON Schema，系统必须先检测能力，并提供“JSON 模式加本地校验”的显式降级路径。

## 项目目标

- 能区分“提示要求 JSON”“JSON 可解析”“符合业务模式”和“事实有来源”四个层次。
- 能用 Pydantic 定义字段类型、枚举、长度、必填项和禁止额外字段，并生成 JSON Schema。
- 能按兼容接口构造 `response_format=json_schema`，记录模型是否实际支持该参数。
- 能对拒答、截断、解析失败、模式失败和证据失败分别处理，避免无限修复。
- 能以正常、缺失、冲突和恶意文本样例完成可复现验收。

## 项目产物与验收条件

产物是岗位信息模式、提取服务、能力降级说明和至少六条测试记录。

- [ ] 输入原始岗位文本，输出通过 Pydantic 校验的 `JobPosting`，且额外字段会被拒绝。
- [ ] 每个提取字段带原文证据或明确为未知；原文未给薪资时不生成具体数字。
- [ ] 严格模式不可用时返回能力状态并切换到受控降级，而不是静默忽略模式。
- [ ] 解析或校验最多执行一次定向修复；仍失败则进入人工复核队列。
- [ ] 验收证据包含模式文件、六条输入与预期、测试报告、失败分类统计和一次人工抽查。

## 任务分析

### 岗位任务、输入与输出

输入是 UTF-8 岗位文本、模式版本、模型配置和能力标记；输出是已验证对象，或带 `error_type`、字段路径和安全摘要的失败结果。岗位任务的核心不是“让模型写漂亮 JSON”，而是建立数据生产契约：语法由 JSON 解析器判断，结构由 Pydantic 判断，业务规则由独立函数判断，事实依据由证据片段和原文比对判断。

可复现实训使用六条自编文本，覆盖完整信息、缺学历、技能同义词、相互冲突要求、文本内伪指令和超长列表。测试可使用模型响应桩，分别返回合格对象、围栏文本、字段类型错误和额外字段；因此无需真实 API 也能验证全部控制流程。

## 核心知识

### 四层正确性

合法 JSON 只说明括号、引号和类型字面量可以解析，不代表字段齐全。JSON Schema 能描述对象、属性、必需字段、数组元素、枚举和 `additionalProperties`；Pydantic 在应用侧把外部数据转换或拒绝，并给出字段路径。业务约束例如“最低薪资不得高于最高薪资”通常需要模型校验器或独立函数。最后，符合所有类型的虚构值仍是错误，所以关键字段要关联原文证据并进行包含或语义复核。

### 严格结构化输出与能力检测

OpenRouter 的兼容请求可通过 `response_format` 传递 JSON Schema，但只对支持该参数的模型生效。选择模型时应查询支持参数，并可要求路由仅选择支持所需参数的提供方。接口返回“不支持参数”时，应用应标记 `degraded=true`，改用 JSON 模式或清晰提示加本地严格校验；若业务风险不允许降级，就应终止而不是尝试猜测。

### 修复不是掩盖错误

去掉 Markdown 围栏属于确定性清洗，但自动补字段会改变事实。一次定向修复可以把验证错误摘要交给模型，要求只修正类型与遗漏且不得新增事实；修复输入、输出和错误必须留痕。若结果仍失败，返回人工处理。模式应有版本号，新增必填字段是破坏性变化，下游升级前不能直接替换旧版本。

## 工程实现步骤

1. 与数据使用方确定字段字典，为每个字段写类型、是否必需、未知表示、长度和事实证据要求。
2. 用 Pydantic 创建严格模型；对字符串去首尾空白，对技能数组去重但保留原顺序，禁止未声明字段。
3. 生成 JSON Schema 并保存哈希。请求中设置模式名称、`strict: true` 和 `additionalProperties: false`。
4. 在模型目录或能力接口中确认 `response_format` 支持；把模型、提供方和能力检查时间写入运行记录。
5. 收到响应后先检查拒答和 `finish_reason=length`，再解析 JSON、执行模式校验和业务校验。
6. 将错误转换成最小摘要，如 `skills: expected array`，执行至多一次修复；不要把堆栈、密钥或其他样本发回模型。
7. 对证据字段执行原文位置检查；无法对应的值置为未知或使本条失败，不能因为结构正确而放行。
8. 跑六条固定样例，输出通过率、各失败类型数量、平均 Token 和人工抽查结论。

## 关键代码与配置

模式使用严格配置，不接受模型临时增加的解释字段。

```python
from pydantic import BaseModel, ConfigDict, Field

class Fact(BaseModel):
    model_config = ConfigDict(extra="forbid")
    value: str = Field(min_length=1, max_length=120)
    evidence: str = Field(min_length=1, max_length=240)

class JobPosting(BaseModel):
    model_config = ConfigDict(extra="forbid")
    title: Fact
    skills: list[Fact] = Field(max_length=20)
    education: Fact | None = None
```

```python
schema = JobPosting.model_json_schema()
response_format = {
    "type": "json_schema",
    "json_schema": {
        "name": "job_posting_v1",
        "strict": True,
        "schema": schema,
    },
}
```

应用必须对返回文本再执行 `JobPosting.model_validate_json(text)`；不能因为上游声明 strict 就跳过本地验证。

## 调试和常见故障

### 故障案例一：模式声明严格却收到“不支持参数”

- **现象：** 请求返回 400，错误指向 `response_format`；换一个模型后同样代码又能运行。
- **原因：** 所选模型或当前提供方未实现严格 JSON Schema，兼容网关不会让所有模型自动获得该能力。
- **定位：** 查询模型支持参数，记录实际路由与错误体中的参数名；用最小模式请求排除业务 Schema 本身。
- **修复：** 选择明确支持模式的模型并要求参数能力，或进入标记清楚的本地严格校验降级；高风险导入任务直接停止。

### 故障案例二：JSON 合法但技能变成未经证实的列表

- **现象：** 对象通过类型校验，输出包含“深度学习、Kubernetes”，原文只写了 Python。
- **原因：** 模式只约束字符串数组，没有要求每项证据，提示又鼓励“完善技能画像”。
- **定位：** 将每个值的 evidence 与原文做位置比对，发现两个证据句不存在；检查业务提示中的推断措辞。
- **修复：** 将技能元素改成值加证据的对象，删除扩写要求，证据无法对应时拒绝该字段并进入复核。

### 故障案例三：修复循环不断增加费用

- **现象：** 一条畸形输入触发十余次请求，最终仍不能导入，调用成本远高于正常样例。
- **原因：** 捕获所有校验异常后无上限地把完整错误和原回答交给同一模型。
- **定位：** 按 trace_id 统计同一输入哈希的请求次数，确认没有修复上限且错误类型没有变化。
- **修复：** 只允许一次定向修复；相同错误再次出现立即返回人工复核，并把失败样本加入回归集。

## 安全、成本与职业规范提示

岗位文本可能包含联系人、邮箱和诱导指令，采集前应获得使用授权并删除非必要个人信息。结构化输出会被下游系统信任，因此不能直接执行模型生成的 URL、命令或数据库字段。证据位置、模式版本和原文哈希要可审计，但原始敏感文本应按保留策略控制访问。

严格模式可能限制可用模型并改变价格或延迟，应在上线前按实际响应 `usage` 统计，而不是依赖固定价目记忆。模式越复杂不一定越可靠，应让一个字段只承担一个明确含义。学生报告必须区分模型约束、应用校验和人工复核各自承担的责任，禁止把 Schema 合格宣传为事实绝对正确。

## 实训练习

1. 根据自编岗位文本完成 `JobPosting` 数据字典，加入学历未知表示和技能证据；生成并保存 Schema。
2. 为六条输入建立预期：至少两条成功、两条字段未知、一条业务冲突、一条伪指令；用响应桩跑完整流程。
3. 制造字符串代替数组、额外字段和 `finish_reason=length`，证明错误类型不同且不会直接导入。
4. 模拟上游不支持 JSON Schema，比较允许降级与禁止降级两种策略的输出和审计字段。
5. 交付通过率、失败分布、一次修复次数、证据抽查表和复现命令，由同伴随机替换一个响应桩验证。

## 本项目小结

结构化输出是一条分层质量链：模型能力帮助减少格式偏差，JSON 解析检查语法，Pydantic/Schema 检查形状，业务规则检查关系，证据核对约束事实。任何一层都不能代替其他层。清晰的能力降级、一次修复和人工出口使失败可控。下一项目将利用响应中的用量和结束原因，为多轮上下文建立预算。
