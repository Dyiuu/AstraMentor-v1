# 项目八：交付可评测可观测可回滚的 AI 学习服务

## 岗位情境

你所在的项目组要为职业院校交付一套“设备维护实训助理”。应用能够依据指定课程回答问题、生成分步教学计划，并在教师授权后创建故障工单。原型功能已经完成，校方要求进行上线验收：需要证明课程证据不串库、开放式回答达到教学要求、提示注入不能越权、集中实训时性能可接受、故障可观测、版本可回滚。各成员之前分别完成了测试或部署任务，但证据散落，阈值和版本也不一致。

你担任本次交付负责人，要把质量标准、自动回归、效果评测、可观测性、安全、性能成本和容器发布组成一个连续的生产工程闭环。综合项目不是重新开发 Agent，也不是把七份报告简单装订，而是用一个候选版本、一份冻结数据集和一条可追溯发布链完成真实验收。任何结论都应能回到制品、配置、样本、trace 或审批记录。

四学时现场任务以现有可运行应用为基础，聚焦上线准备、故障演练和交付决策。若发现阻断问题，应做出拒绝发布或回滚决定；“按计划上线”不是预设答案，基于证据停止发布同样是合格的职业行为。

## 项目目标

完成本项目后，你应能组织跨角色上线验收，把业务风险映射到自动测试、效果量表、在线 SLI 与部署门禁；能为同一候选制品建立不可变身份，执行离线评测、对抗测试、阶梯压测和故障演练；能根据门禁做出发布、限范围发布或拒绝发布的决策，并在异常时完成回滚和证据归档。

最终能力体现在闭环而非单项高分：质量标准决定测什么，测试与评测提供上线前证据，观测验证真实运行，安全与容量限制副作用，持续交付保证制品一致，回滚演练证明恢复能力。交付负责人还应能够向教师、开发、运维和安全人员解释结论及剩余风险。

## 项目产物与验收条件

项目输入包括一个可运行的职业学习 Agent、冻结课程资料、候选镜像、质量标准、二十条以上验收样本、工具替身、目标负载和目标环境。输出包括生产就绪检查表、自动测试报告、效果评测报告、安全演练记录、性能成本报告、可观测仪表板、发布与回滚记录、风险接受或拒绝发布决定。验收证据统一放入带版本的交付包。

- 所有报告引用同一源码提交、镜像摘要、课程索引和配置版本。
- 自动测试在断网环境运行，高风险护栏被破坏时能够准确失败。
- 效果报告包含总体、课程与风险切片，跨课程引用为零。
- 注入与越权样本不会触发高影响工具，人工确认可审计。
- 目标负载下首字与总延迟、错误率和单位任务成本达到批准阈值。
- 告警能够下钻到 trace，至少完成一次模型超时或工具失败定位。
- 候选发布失败时恢复上一制品及兼容数据，并通过核心冒烟。
- 最终审批记录列出已知限制、责任人、期限和复测条件。

交付包中的“输入、输出、验收证据”必须逐项对应。若某项未执行，应明确标记未验证及其影响，不能用空白或口头说明替代。

## 任务分析

综合验收按风险优先排序。先冻结版本和证据范围，避免测试过程中制品变化；再运行便宜、确定的门禁，阻断明显缺陷；之后开展效果、安全和负载验证；候选进入测试环境后检查遥测与生命周期；最后执行故障和回滚演练。每一阶段只有满足进入条件才能继续，失败会形成修复或停止决定。

### 团队角色与沟通

建议由交付负责人控制运行单，测试人员执行自动门禁，课程教师完成关键效果复核，安全人员观察高风险工具，运维人员负责部署与回滚。角色可以由学生轮换，但同一关键结果至少有执行者和复核者。所有时间、决定和偏差写入共同记录，避免故障时多组使用不同版本。

## 核心知识

### 生产就绪是证据链

生产就绪不是单一“上线评分”。它是一组相互约束的主张：功能按契约工作，内容在目标任务上有效，高影响风险被限制，负载在容量内可预测，异常能够被发现和恢复。每个主张都要有证据、版本和责任人。证据之间若版本不一致，例如性能报告测试旧模型、安全报告测试新工具，就不能共同支持候选发布。

可以建立追踪矩阵：风险 ID 对应控制、测试、指标、告警、运行手册和审批项。跨课程引用风险对应 Retriever 隔离测试、效果挑战样本、线上 `course_id` trace 字段和事故排查手册；工具越权风险对应权限策略单测、对抗样本、工具拒绝指标与人工确认审计。这样某个控制变化时可以找到全部受影响证据。

### 门禁顺序与决策类型

门禁顺序应先确定性、高严重度，后开放式和高成本。制品身份、配置解析、单元测试和安全阻断失败时无需继续消耗模型评测预算。通过基础门禁后再做效果、对抗和性能；部署后验证探针与观测；最后回滚演练。每个阶段设置停止条件，避免团队因已经投入时间而继续推动危险版本。

最终决策可分三类：发布表示全部阻断项通过且剩余风险在容忍范围；限范围发布表示只对指定课程、角色或流量开放，并有自动到期和扩大条件；拒绝发布表示存在阻断失败或证据不足。例外不是第四种随意路径，它必须明确风险所有者、补偿控制、期限和复测。

### 故障演练与恢复验证

演练选择可控、可恢复且能检验关键假设的故障，例如模型首字超时、Retriever 索引过期、工具 503 或 readiness 失败。演练前确认停止条件和隔离环境，演练中记录告警、trace、决策与用户影响，恢复后验证错误率、队列、状态和核心任务。只恢复 HTTP 200 不足以证明服务恢复，必须完成课程检索、流式教学和会话读取。

回滚要核对镜像、配置、课程索引和持久数据的兼容组合。若版本切换成功但安全策略或模型路由仍是候选配置，实际并未完整恢复。交付包保存制品摘要、配置版本和恢复证据，为后续事故提供基线。

### 交付与持续改进

验收数据集和阈值不是永久不变。上线后从经脱敏的真实失败、告警和教师反馈补充回归，但保持独立保留集，避免过拟合。事故复盘要新增控制或验证，而不是只要求人员“以后注意”。生产观测发现的漂移触发重新评测，教材、模型、工具或权限重大变化触发部分或完整再认证。

## 工程实现步骤

### 步骤一：冻结候选制品与运行单

记录源码提交、镜像摘要、课程清单与索引 schema、模型别名、提示版本、工具策略和数据集版本。检查交付环境没有本地手改。将质量标准中的阻断项写入运行单，指定每项执行者、证据路径和停止条件。

### 步骤二：执行离线质量与安全门禁

在断网环境运行单元、组件和课程隔离测试，随后对冻结样本执行效果评测。教师盲审高风险与低一致性样本。使用假工具执行直接注入、恶意教材、跨用户记忆和参数越权测试，记录策略拒绝原因与模型调用、工具执行次数。

### 步骤三：执行容量测试并部署候选

按预定阶梯负载运行，记录 P50/P95 首字、总延迟、队列、错误、Token 与单位成功成本，同时抽样检查答案质量。达到目标且无安全退化后，通过流水线部署候选摘要。验证 startup、liveness、readiness、配置注入、非 root 用户和持久卷。

### 步骤四：完成观测、故障和回滚闭环

从一个学习请求沿 trace 检查检索、模型、工具和状态 span。注入已批准故障，观察 SLO 告警并按运行手册定位。让候选版本触发停止条件，执行回滚；验证旧版读取会话和课程后，由各角色共同签署发布或拒绝决定，归档全部证据哈希。

## 关键代码与配置

下面的简化门禁函数强调阻断项优先。实际流水线会从各测试报告读取结构化结果，并保存每一条失败证据。

```python
def release_decision(report):
    blockers = [
        report["cross_course_citations"] > 0,
        report["unauthorized_tool_calls"] > 0,
        not report["rollback_verified"],
        report["evidence_incomplete"],
    ]
    if any(blockers):
        return "reject"
    if report["p95_first_token_ms"] > report["slo_first_token_ms"]:
        return "limited_release"
    if report["task_success_rate"] < report["minimum_task_success"]:
        return "reject"
    return "release"
```

程序输出只是执行已批准规则，不能替代风险负责人审批。`limited_release` 必须附带范围、观测指标、停止阈值和自动到期时间，否则按拒绝发布处理。

## 调试和常见故障

### 故障一：所有子报告通过，综合验收无法签字

**现象：** 测试、评测和性能报告分别显示绿色，审批人发现它们使用了不同模型与课程索引版本。**原因：** 各小组独立运行，没有冻结候选身份，报告只写日期没有不可变摘要。**定位：** 比对报告中的源码、镜像、模型配置、数据集和索引哈希，列出无法对应候选的证据。**修复：** 建立统一运行单和制品清单，流水线向每份报告注入同一候选元数据；版本不一致的结果作废重跑，门禁增加证据完整性检查。

### 故障二：回滚后错误率恢复但学习状态丢失

**现象：** 旧镜像启动、接口成功率正常，学生历史进度为空。**原因：** 回滚只切换应用制品，候选版曾改变状态目录或格式，备份未纳入演练。**定位：** 检查卷挂载、状态 schema、备份时间与恢复日志，用已知会话 ID 比较升级前后文件。**修复：** 把数据兼容、备份和恢复纳入发布计划，使用向后兼容格式或可逆迁移；回滚冒烟必须验证历史会话、课程身份和步骤进度，而非只检查根路由。

## 安全、成本与职业规范提示

综合演练会集中使用模型、工具、遥测和部署权限，必须采用隔离环境、临时最小权限角色和调用预算。真实工单、通知和设备控制全部由替身接管。交付包可能包含攻击样本、失败输出和内部拓扑，要分级存储；对外汇报使用脱敏摘要，不公开可复现生产攻击的敏感细节。

不能为了按期答辩篡改阈值、删除失败样本、替换候选版本或把未执行项写成通过。拒绝发布是质量工程的正常产出。若接受临时风险，审批者必须有相应授权，并记录影响范围、补偿控制、期限和负责人。学生团队的每个结论都应区分观测事实、风险判断和处置建议。

完整验收可能消耗较多模型与压测资源，应按照门禁顺序提前停止失败版本。评测缓存只在候选输出、量表和裁判版本完全一致时复用。演练结束后关闭临时资源和提高的采样率，确认没有后台任务继续计费。

## 实训练习

选择一个已完成的 RAG 或 Agent 应用，建立至少十二项生产就绪运行单。冻结制品、课程索引、配置和二十条效果样本，执行自动测试与盲化效果评审。构造恶意教材和越权工具参数，证明策略执行器阻断真实副作用；随后以阶梯负载验证首字延迟和单位任务成本。

把候选部署到隔离环境，选择模型超时或 readiness 失败进行演练。要求从告警找到 trace，依据停止条件触发回滚，并验证一个历史会话和一条课程流式问答。最终进行十分钟上线评审陈述：给出发布类型、三条关键证据、两个剩余风险和各自跟踪责任人。

## 学习评价量表

| 评价维度 | 优秀（90—100） | 合格（60—89） | 需改进（60以下） | 权重 |
|---|---|---|---|---:|
| 证据一致性 | 所有报告绑定同一不可变候选 | 主要版本信息一致 | 报告无法对应候选 | 15% |
| 质量与效果 | 自动回归、量表、切片和失败归因完整 | 完成主要验收 | 只有演示或单一模型分 | 20% |
| 安全与权限 | 注入、越权、隔离和确认均有证据 | 完成核心安全测试 | 高影响工具产生副作用 | 20% |
| 性能与观测 | 容量、成本、SLO、trace 可关联 | 有负载和监控结果 | 只看平均值且无法排障 | 15% |
| 部署与恢复 | 制品、探针、数据、回滚全链演练 | 能部署并回到旧版 | 手工改生产或状态丢失 | 20% |
| 决策与职业规范 | 结论透明、例外有期限、交付可复核 | 能说明通过与限制 | 隐瞒失败或无授权放行 | 10% |

存在跨课程引用、未经确认的高影响工具调用、真实敏感数据泄露或回滚不可恢复时，综合项目直接判定不通过。

## 本项目小结

综合生产交付把七类能力串成同一证据链：质量标准规定目标，自动测试保护确定契约，效果评测检查开放结果，可观测性连接线上因果，安全策略限制副作用，性能工程建立容量边界，容器与持续交付保证制品可复现和可恢复。缺少任何一环，都可能让“能演示”的原型在真实教学中失控。

专业交付的标志不是永远选择发布，而是依据一致版本和透明证据做出可审计决定。运行单、停止条件、故障演练和回滚验证把不确定性转化为受控过程。上线后仍需从新故障和真实反馈更新测试与评测，使质量闭环持续运行。
