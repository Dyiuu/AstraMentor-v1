# 项目7：建立分层的 RAG 评测体系

## 岗位情境

知识助手已经能返回带引用答案。产品经理用五个问题体验后认为“效果很好”，检索工程师则只报告平均相似度；一次切分改动让 Recall@5 上升，却使拒答问题开始胡乱作答，团队直到演示才发现。你要建立版本化评测流水线，分别测语料、召回、排名、依据答案、引用、拒答、延迟和成本，并把高风险子集设置为发布门槛。

评测不是用一个模型分数替代责任判断。规则指标、人工量表和可选模型裁判各有边界；模型裁判需校准、记录提示与版本，并接受人工抽查。

## 项目目标

- 能构建开发集、冻结验收集和挑战集，并防止答案泄漏到查询。
- 能计算 Recall@K、MRR、引用有效率、拒答正确率等可解释指标。
- 能按问题类型和风险分层，定位文档、切分、检索、重排或生成环节故障。
- 能设计人工评价量表和模型裁判校准样本，报告分歧而不是隐藏。
- 能建立基线、候选版本、置信区间/样本量说明和发布回滚门槛。

## 项目产物与验收条件

产物为评测 JSONL、运行器、指标报告、失败分类表和发布决策模板。输入为冻结问题集、检索中间结果、结构化答案与版本配置；输出为逐问记录、聚合指标和发布结论；验收证据覆盖人工复核、分歧和回滚判断。

- [ ] 至少 30 问划分为开发 15、冻结验收 10、挑战 5；每问有 answerability、证据和风险。
- [ ] 检索报告包含 Recall@1/5、MRR、无命中率和越权命中数；生成报告包含依据、相关、引用和拒答。
- [ ] 每次运行记录 corpus/index/prompt/model/evaluator 版本、随机参数、时间、延迟与用量。
- [ ] 高风险可回答问题必须命中证据，高风险不可回答问题必须正确拒答；任何越权命中阻断发布。
- [ ] 验收证据含基线/候选差异、逐问结果、至少五例人工复核、分歧记录、失败归因和回滚结论。

## 任务分析

### 岗位任务、输入与输出

输入是冻结数据集、待评系统配置、检索结果、结构化答案、引用 Ledger、人工或裁判评分器；输出是逐问记录、聚合指标、风险分层和 pass/fail 决策。评测运行器必须保存原始中间结果，使低分可以回溯到“期望证据没进 Top-K”还是“证据已进但答案未使用”。

可复现实训扩展前述问题集为 30 问，候选系统通过改变重叠或 RRF 参数模拟。使用固定模型响应桩评估流程确定性；如使用真实生成，温度、模型快照和重试写入报告。两名同学独立审阅五条答案，比较依据/相关评分分歧并裁决。

## 核心知识

### Recall@K 与 MRR

对有标注相关证据的问题，Recall@K 是前 K 结果覆盖的相关证据数除以全部相关证据数；若任务只要求任一支持证据，也可报告 hit@K，但必须写清定义。MRR 使用第一个相关结果名次的倒数，强调正确证据靠前。不可回答问题没有 expected evidence，不应硬算 Recall，而应检查是否正确识别无依据并拒答。

### 答案与引用指标

问题相关性检查回答是否解决用户问题；依据一致性检查关键主张能否由提供证据支持；引用有效率检查 ID 是否存在；引用支持率检查被引片段是否支持对应主张；拒答正确率同时关注该拒答时拒答和该回答时回答。指标命名须附公式或量表，避免团队对“准确率”理解不同。

### RAGAS 与模型裁判边界

RAGAS 原始研究提出在缺少人工参考答案时评价 RAG 的多个方面，为自动诊断提供思路。但模型裁判可能受提示、模型版本、答案顺序和语言影响，不能当作客观真值。应使用人工金标样本校准，报告与人工一致率及分歧；高风险失败由人审，裁判输入也需经过数据授权。

### 失败分类与发布门槛

一个错误可归因于 source_missing、parse_loss、bad_chunk、retrieval_miss、rank_too_low、context_drop、unsupported_claim、wrong_citation、should_refuse 或 latency_error。先定位最早失败环节，避免通过改提示掩盖语料缺失。发布比较逐问差异和风险子集，不能只看平均数；越权命中和高风险错误答案是硬门槛。

## 工程实现步骤

1. 冻结语料与 30 问，保存 dataset_version、来源许可、标注者和证据位置；哈希防止运行中被改动。
2. 按问题类型、answerability、风险、自然表达和版本冲突分层划分，开发集调参，验收集只做发布判断。
3. 评测运行器为每问保存 Top-K hit、阶段 rank、最终上下文、答案、引用、状态、用量、延迟和错误。
4. 实现 Recall@K、MRR、hit@K、越权数、引用 ID 有效率和拒答混淆矩阵；对分母为零给出 not_applicable。
5. 制定 0/1/2 人工量表：依据、相关、完整、引用支持和安全；两人独立审五条并记录分歧原因。
6. 若启用模型裁判，用同五条金标校准，固定裁判提示/模型/输出 Schema；偏差过大则不用于发布门槛。
7. 运行基线与候选，逐问 diff；为每个退化样例定位最早失败阶段，估算修复影响后再改一个变量。
8. 生成总体、类型、风险报告和发布结论；保存候选配置与回滚指针，验收集失败不得“改标签”放行。

## 关键代码与配置

下面实现把没有相关证据的可回答问题视为数据错误，而不是除零。

```python
def recall_at_k(ranked: list[str], relevant: set[str], k: int) -> float:
    if not relevant:
        raise ValueError("Recall 只适用于已标注相关证据的问题")
    return len(set(ranked[:k]) & relevant) / len(relevant)

def reciprocal_rank(ranked: list[str], relevant: set[str]) -> float:
    for rank, item in enumerate(ranked, start=1):
        if item in relevant:
            return 1.0 / rank
    return 0.0
```

## 调试和常见故障

### 故障案例一：Recall@5 提升但高风险回答退化

- **现象：** 总体 Recall 从 0.82 升至 0.88，两个安全操作问题却引用错误版本并直接作答。
- **原因：** 报告只看总体平均，新增候选扩大召回却没有版本过滤和高风险门槛。
- **定位：** 按 risk/intent 分层对比逐问结果，追踪错误 hit 的 version 与权限过滤阶段。
- **修复：** 恢复生效版本过滤，高风险集单独设置证据命中和拒答硬门槛；均值不能覆盖阻断失败。

### 故障案例二：模型裁判给伪引用答案高分

- **现象：** 自动依据分为 2，人工发现答案的 S9 不在 Ledger，数字也无证据。
- **原因：** 裁判提示只让评价语言合理性，没有提供 Ledger 或要求逐主张核对。
- **定位：** 用已知伪引用金标复跑裁判，比较裁判解释和人工标注，确认校准失败。
- **修复：** 未知 ID 先由确定性规则判零；裁判只处理语义支持，并以金标一致性决定是否可用。

### 故障案例三：候选版本通过是因为验收集被改过

- **现象：** 一条检索失败问题从验收数据消失，报告却没有数据集版本变化说明。
- **原因：** 开发与验收使用同一可编辑文件，调参人员为匹配当前系统修改标签。
- **定位：** 对比 dataset checksum、Git 差异和运行记录，发现哈希与基线不一致。
- **修复：** 冻结验收集并限权，任何修订走标注纠错审批并产生新版本；旧报告只与同版本比较。

## 安全、成本与职业规范提示

评测集包含真实问题模式和可能的敏感表达，应去标识化并限制访问。越权测试用虚构受限材料和测试身份，不复制真实隐私。将答案交给外部裁判前确认数据授权；高风险结论由具备业务职责的人审，算法工程师不能单独签署安全操作正确性。

全量生成评测会产生费用，可分层运行：提交时先跑本地检索和固定桩，每日跑小规模生成，发布前跑冻结全集。缓存必须以系统/语料/提示/模型版本共同作为键。报告公开样本量和不确定性，样本很少时不使用小数点制造虚假精确。

## 实训练习

1. 将 30 问按规定划分，生成 checksum，检查每条可回答问题有证据、每条不可回答问题有期望状态。
2. 实现 Recall@1/5、MRR、引用 ID 有效率和拒答混淆矩阵，用手算小例验证。
3. 两人独立评分五条，计算完全一致数量，分析至少一个分歧并形成裁决规则。
4. 运行基线/候选逐问 diff，故意加入旧版 hit 和伪引用，证明硬门槛阻断发布。
5. 提交机器可读结果、聚合报告、失败分类、成本时延、数据集哈希、复现命令和回滚结论。

## 本项目小结

分层评测把 RAG 的模糊“效果”拆成可定位证据：Recall 与 MRR衡量检索，主张与引用衡量依据，混淆矩阵衡量拒答，延迟和用量衡量服务。冻结数据、版本记录和风险硬门槛防止过拟合与平均数掩盖。模型裁判只能在人工校准后辅助。最后一个项目将用这一体系验收完整职业课程知识助手。
