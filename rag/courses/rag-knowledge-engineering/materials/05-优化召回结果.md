# 项目5：用混合检索与重排序优化召回

## 岗位情境

两条索引已上线测试。查询课程编号时 BM25 排名第一，向量检索却把相近课程排在前面；学生问“模型乱编怎么控制”时向量能找到“幻觉抑制”，BM25 因没有相同词而漏掉。团队直接把两个 score 各乘 0.5 相加，结果不同模型或语料重建后排序剧烈变化。你需要建立混合检索：先在统一权限过滤下并行召回，用 Reciprocal Rank Fusion 融合排名，再对小候选集重排序，并对歧义查询做受控改写。

本项目优化候选证据，不生成最终答案。任何优化必须在冻结开发集上比较并用独立验收集确认，不能在正文隐藏关键词迎合用例。

## 项目目标

- 能诊断关键词、向量路径各自的强项、失败类型和 score 尺度差异。
- 能实现保留原查询的多路召回，并使用 RRF 融合不同排名。
- 能在检索前执行 metadata 过滤，在融合后进行近重复去除与来源多样性控制。
- 能对 Top-N 候选使用重排器，平衡 Recall、精确性、延迟与费用。
- 能设计查询改写保护规则，避免编号、否定、时间和权限条件被改丢。

## 项目产物与验收条件

产物为 HybridRetriever、RRF 实现、可选 reranker、查询诊断日志和对比报告。

- [ ] 输入 query、course_id、身份过滤和 top_k，输出带 lexical_rank、dense_rank、rrf_score、rerank_score 的 SearchHit。
- [ ] 原查询始终参与召回；改写查询作为附加路径，并保留编号、日期、否定和引用范围。
- [ ] 权限过滤在每条候选路径执行，融合结果不包含越权或失效文档。
- [ ] 重排序只处理限定候选数，超时可回退 RRF 排名并标记 degraded。
- [ ] 验收证据包含十问基线/混合/重排对比、P95 延迟、唯一来源数、失败归因和配置版本。

## 任务分析

### 岗位任务、输入与输出

输入包括原始查询、可选澄清字段、用户权限过滤、BM25/向量索引、融合常数、候选上限与重排器；输出是可解释候选列表和每阶段诊断。岗位任务不是盲目堆算法，而是对问题类型分层：精确标识、领域术语、同义表达、否定条件、版本时间和跨章节问题需要不同观察。

可复现实训从需求问题集中选十问，冻结目标 evidence_ids。为每问保存 BM25、dense、RRF、rerank Top-10 和时延。重排可用确定性评分桩验证管线，也可在授权时使用模型；所有模式都必须保持同一权限过滤与候选输入，便于公平比较。

## 核心知识

### 混合检索互补而非替代

词法路径保留确切符号、编号与罕见术语，稠密向量路径补足同义和概念表达。混合查询应让两条路径接收同一课程、版本、时间和权限过滤。只有向量无命中不代表词法也应放弃；一个路径失败时可以用另一条形成降级，但响应必须记录路径状态。

### Reciprocal Rank Fusion

RRF 按文档在多个结果列表中的名次累加 `1/(k+rank)`，不要求 BM25 分数与余弦相似度在同一尺度。出现在多个高位列表的文档获得更高融合分。常数与每路候选数仍需在开发集验证；同一 chunk 在一个列表中只计一次。RRF 不自动解决权限、重复或错误候选，它只组合给定排名。

### 查询改写的保护规则

改写可以展开简称、补充领域同义词或生成多个检索子句，但必须保留原查询作为一路。课程编号、API 名、版本日期、引号短语、否定词和身份过滤是受保护实体，不能被语言模型随意改写。若问题含“它、那个流程”等对话指代，应从受信任会话状态补充，而不是让改写器发明对象。

### 重排序与成本

重排器用更深的查询—文档交互重新排列小候选集，通常比对全库运行昂贵模型更可控。候选 N 太小可能丢失证据，太大会增加延迟和费用。重排输入包含标题路径和正文，但要限制字符并保持证据位置。超时、配额或模型不可用时回退 RRF，不能返回空列表冒充无证据。

## 工程实现步骤

1. 按问题类型统计两条基线 Recall@5、MRR、唯一来源数和延迟，逐问标记词法赢、向量赢、均失败。
2. 解析并锁定 course、access、version、effective_time 等过滤，在 BM25 与 dense 查询前应用同一过滤。
3. 每路取 Top-20，按 chunk_id 去重，记录 rank；实现 RRF 并保留每路贡献，输出候选 Top-10。
4. 对相邻重叠块做近重复合并，优先保留分数更高且证据范围完整者；设置每文档最大占位数。
5. 仅对歧义或同义失败类启用查询改写，提取受保护实体并在改写后断言仍存在；原 query 永远保留。
6. 将 RRF Top-20 送重排器，输入标题与裁剪正文；设置短超时，失败时标记 `rerank_degraded` 并使用 RRF。
7. 运行十问并记录各阶段 Top-K、Recall、MRR、延迟和费用；在独立验收问题上确认没有过拟合。
8. 固化融合常数、候选数、重排模型和改写版本，任何变更都可回滚到 BM25/dense 基线。

## 关键代码与配置

RRF 只依赖名次，返回值可解释为各路贡献之和。

```python
from collections import defaultdict

def rrf(rankings: list[list[str]], k: int = 60) -> list[tuple[str, float]]:
    scores = defaultdict(float)
    for ranking in rankings:
        seen = set()
        for rank, chunk_id in enumerate(ranking, start=1):
            if chunk_id in seen:
                continue
            seen.add(chunk_id)
            scores[chunk_id] += 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda item: (-item[1], item[0]))
```

## 调试和常见故障

### 故障案例一：直接相加原始分数后向量路径长期支配

- **现象：** BM25 对课程编号给出第一名，但融合结果把它排到十名以后；更换 embedding 后现象反转。
- **原因：** BM25 与余弦分数范围和分布不同，固定 0.5 权重不具有稳定含义。
- **定位：** 绘制两路 score 分布与 rank，确认排序信息合理但数值尺度不可比。
- **修复：** 改用 RRF 等基于排名的方法，保留每路贡献；在冻结十问上重新选择候选数和常数。

### 故障案例二：查询改写丢失否定和版本

- **现象：** “2025 旧版是否禁止带电检修”被改成“带电检修步骤”，召回当前操作说明。
- **原因：** 改写器追求简短语义，没有锁定日期、旧版与否定词，且原查询被替换。
- **定位：** 对照 original_query、rewrites 与提取实体，发现保护集合缺失；查看哪一路贡献最终 hit。
- **修复：** 原查询永远保留；对编号、时间、引号和否定做确定性检查，丢失即弃用该改写并记录 rejected。

### 故障案例三：重排服务超时导致无结果

- **现象：** 两路召回正常，页面却显示“知识库无内容”，日志只有重排超时。
- **原因：** 管线把 reranker 当必须步骤，异常后清空候选而非降级。
- **定位：** 分阶段保存候选计数，确认 RRF 有十条而 final 为零；检查异常处理分支。
- **修复：** 超时回退已通过权限过滤的 RRF 排名，响应标记 degraded；指标区分真正零命中与优化器故障。

## 安全、成本与职业规范提示

每条召回和改写路径都必须执行权限过滤，不能先混入受限文档再在最终 Top-K 删除，因为排名与日志已经受到泄露影响。查询本身可能含个人信息，改写日志应脱敏并设保留期。外部重排服务会接触 query 与候选文本，只有在数据授权允许时使用。

优化报告同时呈现质量、P95 延迟、重排调用率和单位查询费用。不能用“平均 Recall 上升”掩盖高风险问题退化；高风险子集设单独门槛。查询改写与重排模型的版本必须记录，输出用于排序而非改变原文证据。

## 实训练习

1. 对十问分别运行 BM25 与 dense，按类型标注胜负和失败原因，保存 Top-10 证据 ID。
2. 实现 RRF 并手算一个两列表例子，验证代码分数与预期一致；检查相同 ID 不重复计分。
3. 构造含课程编号、日期和否定的查询，生成改写并验证保护实体；故意丢失时必须拒绝该改写。
4. 模拟 reranker 超时，证明 final 仍返回 RRF 结果并带 degraded；权限角色的结果始终无受限块。
5. 提交基线/融合/重排的 Recall@5、MRR、P95、唯一来源和费用表，以及配置与复现命令。

## 本项目小结

混合检索用词法精确性和向量语义能力共同扩大候选覆盖，RRF 以排名融合避免原始分数尺度陷阱。受保护的查询改写、近重复控制和小候选重排进一步提高前列相关性，而权限过滤与失败回退贯穿全部路径。下一项目将消费这些候选，建立带引用、可拒答的依据生成接口。
