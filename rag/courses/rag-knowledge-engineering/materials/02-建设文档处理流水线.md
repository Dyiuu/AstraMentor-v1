# 项目2：建设可追溯的文档处理流水线

## 岗位情境

需求基线批准了 Markdown 教材、PDF 制度和三页公开网页。旧脚本把所有文件转成一个大字符串，PDF 页眉重复数十次，网页菜单混入正文，Markdown 代码与标题层级丢失；后续答案引用只能显示“来自知识库”，无法定位原文件和页面。你需要交付可重复的文档处理流水线，将异构来源转成统一 Document，同时保留来源、版本、章节、页码或行号、权限和内容哈希。

本项目的终点是标准化文档集，不提前选择 chunk 大小或构建检索索引。解析失败必须显式进入隔离报告，不能以空文本悄悄通过。

## 项目目标

- 能定义原始文件、解析结果和标准 Document 的不可变边界。
- 能按来源类型解析 Markdown、文本型 PDF 和允许网页，保留可引用结构。
- 能识别扫描 PDF、重复页眉、导航噪声、编码错误和内容更新。
- 能用哈希、解析器版本和构建清单实现增量处理与可复现重建。
- 能在抓取、临时文件、权限、许可与个人信息方面遵守职业规范。

## 项目产物与验收条件

产物为 Document 模型、三个解析适配器、构建清单、隔离报告和标准化 JSONL。

- [ ] 输入批准的 Markdown/PDF/HTML 样本，输出 `document_id/text/metadata/blocks`，关键字段非空。
- [ ] metadata 至少含 course_id、source_uri、source_type、title、version、checksum、access、parser_version。
- [ ] Markdown 标题和代码块、PDF 页码、网页主内容边界可回溯；原始行号可用时保留。
- [ ] 扫描件、加密 PDF、空正文、越界路径和未授权 URL 分别产生明确隔离原因。
- [ ] 验收证据包括固定样本哈希、两次重建一致性、解析统计、十条位置抽查和隔离文件列表。

## 任务分析

### 岗位任务、输入与输出

输入是来源登记表、允许根目录或 URL 清单、原始字节、文档版本和权限；输出是规范化 Document 序列与 build manifest。每条块记录文本、块类型、章节路径、页码/行号等定位信息。原文件作为证据源保持只读，标准化结果是可再生成产物，二者用 checksum 关联。

可复现实训准备含多级标题与代码的 Markdown、三页带重复页眉的文本 PDF、含菜单与正文的静态 HTML、一个扫描 PDF 和一个错误编码文本。运行两次流水线，比较排序后的 JSONL 哈希；再随机抽十个块回到原文定位。扫描件只识别并隔离，不要求本单元实现 OCR。

## 核心知识

### 统一 Document 与块

Document 是来源级实体，block 是保留结构的内容单元。正文不应与所有元数据拼成不可逆字符串。一个稳健契约把稳定 `document_id`、显示标题、来源 URI、内容哈希、版本、权限和解析器版本放在 metadata，把标题、段落、表格、代码等按原顺序放入 blocks。后续切分可以组合 blocks，但引用仍能回到原始位置。

### PDF 文本提取的边界

pypdf 官方说明 PDF 不包含“语义段落”这一简单结构，文本位置与阅读顺序可能难以恢复；扫描 PDF 只有图像，普通文本提取不会自动完成 OCR。页眉页脚、分栏、连字符和表格需要样本化验证。工程上保留 page_number，并将低文本密度或提取异常送往 OCR/人工流程，不能假装空页没有内容。

### Markdown 与网页结构

Markdown 标题天然适合作为章节路径，代码围栏和表格要作为独立块保留，避免清洗正则吞掉符号。网页只抓需求清单中的 HTTPS 地址，遵守站点许可与更新规则；解析主内容时排除导航、脚本和页脚，但保留标题、永久链接与抓取时间。动态页面或需要登录的页面不能由简单 HTML 请求可靠获取，应明确列为另一数据接入任务。

### 确定性与增量

同一输入、相同解析器版本和配置应产生相同顺序与内容。构建清单记录原始 checksum、输出 checksum、解析器、状态和时间。原哈希未变可复用结果；发生变化只重建对应文档。使用路径字符串作 ID 会在移动目录后破坏历史引用，因此可用课程内稳定 ID 与发布版本组合。

## 工程实现步骤

1. 定义 Document/Block JSON Schema，明确必填字段、允许块类型、页码从 1 开始及行号范围语义。
2. 根据来源登记表建立 allowlist；本地路径解析后必须位于课程材料根目录，URL 必须为批准的 HTTPS host 和固定路径。
3. Markdown 适配器逐行识别标题栈、围栏代码、表格和段落，为每块保存 start_line/end_line。
4. PDF 适配器逐页提取文本，保留 page_number；统计字符密度、空页和重复短行，异常送隔离而非丢弃。
5. HTML 适配器只解析已下载固定样本，移除 script/style/navigation，保留 canonical URL、标题和抓取时间。
6. 规范 Unicode 与换行，合并明显断行但不任意改写内容；重复页眉规则必须有频次证据和白名单。
7. 计算原始和标准化 checksum，写 build manifest。输出按 document_id 与块序稳定排序，采用 UTF-8 JSONL。
8. 两次重建比较哈希，人工抽十块回溯原位置；汇总成功、警告、隔离及字符数量。

## 关键代码与配置

Document 契约把正文块与可过滤元数据分开。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Block:
    kind: str
    text: str
    section_path: tuple[str, ...]
    page: int | None = None
    start_line: int | None = None

@dataclass(frozen=True)
class Document:
    document_id: str
    blocks: tuple[Block, ...]
    metadata: dict
```

```json
{
  "document_id": "welding-safety-2026",
  "metadata": {
    "source_type": "pdf",
    "source_uri": "materials/welding-safety-2026.pdf",
    "version": "2026.1",
    "access": "student",
    "parser_version": "pdf-v1",
    "checksum": "sha256:EXAMPLE_CHECKSUM"
  }
}
```

## 调试和常见故障

### 故障案例一：扫描 PDF 被当作空文档

- **现象：** 文件有二十页可见文字，JSONL 中 text 为空，流水线仍显示 success。
- **原因：** 页面是图像，文本提取器没有 OCR；程序又只以“未抛异常”判断成功。
- **定位：** 记录页数、每页提取字符数与图像对象，人工打开样本确认内容类型。
- **修复：** 设置最低文本密度与空页比例，标记 `ocr_required` 并隔离；由批准的 OCR 流程处理后重新进入版本化管道。

### 故障案例二：正常正文被页眉去重规则删除

- **现象：** 每页开头相同的安全警示被全部删掉，而它正是回答必须引用的规则。
- **原因：** 清洗器把任何重复短行都视为页眉，没有位置、语义或保留白名单。
- **定位：** 比较清洗前后行统计和页内坐标，抽查被删除文本在页面中的作用。
- **修复：** 去重规则同时考虑固定页边位置、出现频次和明确模式；关键警示加入保留规则，清洗日志记录每条删除原因。

### 故障案例三：文件移动后引用全部失效

- **现象：** 只调整材料目录，内容未变，所有 document_id 改变，历史答案无法定位。
- **原因：** 直接以绝对路径哈希作为稳定 ID，把存储位置与内容身份混为一体。
- **定位：** 比较移动前后 checksum 与 document_id，确认内容哈希一致但 ID 变化。
- **修复：** 使用清单中稳定业务 ID 与版本；source_uri 可更新但保留映射，历史版本仍能解析到归档来源。

## 安全、成本与职业规范提示

解析器面对不可信文件，应限制字节、页数、解压规模、处理时长和内存，并保持依赖更新。路径先 `resolve` 再验证位于允许根，禁止 `..` 越界。网页抓取遵守授权、许可、robots 和访问频率，不登录抓取受限内容。原文件、标准化输出和隔离样本的权限至少与来源同级。

OCR、动态网页和复杂表格会显著增加成本，需求阶段应按价值分批接入。清洗不是改写教材，删除或合并都必须可解释和抽查。文档工程师在报告中披露扫描件、分栏和表格的已知限制，不能用“解析成功”掩盖内容缺失。

## 实训练习

1. 为五类固定样本生成来源清单和 checksum，定义预期状态及定位字段。
2. 实现三类适配器，输出稳定排序 JSONL；连续运行两次比较输出哈希。
3. 复现扫描件空文本并改为 `ocr_required`；证明它不会进入标准文档集。
4. 对重复页眉规则做前后差异审阅，抽查十个块的页码/行号能回到原文。
5. 提交构建命令、解析统计、隔离报告、路径安全测试和来源许可说明，验收者替换一个原文件验证只重建该文档。

## 本项目小结

文档流水线把异构文件转换为后续检索可依赖的证据资产。统一 Document、结构化 blocks、稳定 ID、版本权限、checksum 和位置映射共同保证可追溯；解析统计与隔离让扫描件等限制可见。确定性重建避免每次构建产生无意义变化。下一项目会在保留这些证据边界的前提下设计标题感知切分。
