# 项目4：建立可持久化的关键词与向量检索索引

## 岗位情境

标题感知 Chunk 已通过审阅。团队用内存字典做关键词包含查询，能够找到精确课程编号，却无法处理同义表达；另一名成员临时加入向量搜索，每次启动都重新计算 embedding，索引与材料版本不一致。你需要建设两条可独立验收的检索路径：BM25 负责精确术语与稀有编号，向量索引负责语义相近表达，并以构建清单、原子发布和加载校验保证持久化索引与源材料一致。

本项目先建立候选召回，不在此处做混合融合和重排序。embedding 是由模型生成的数值表示，不能从中还原权限；过滤元数据必须随索引保存并在查询时执行。

## 项目目标

- 能说明 BM25 的词频、逆文档频率与文档长度归一化在职业语料中的作用。
- 能选择适配中文的分词/字符策略，并用词典和测试问题验证课程术语。
- 能对 Chunk 批量生成固定维度向量、规范化相似度并构建 Faiss 或等价索引。
- 能持久化文档映射、向量、词法统计、构建配置和源 checksum，并做原子发布。
- 能用精确编号、同义问题、权限过滤和索引损坏场景完成验收。

## 项目产物与验收条件

产物为 BM25Index、VectorIndex、索引 manifest、构建 CLI 与统一 SearchHit。输入为通过验证的 Chunk、分词和 embedding 配置；输出为两套可加载索引及统一命中列表；验收证据覆盖重启、损坏与回滚场景。

- [ ] 同一 Chunk 集构建两个独立索引，查询输出 score、rank、chunk_id、document_id 与证据位置。
- [ ] BM25 能检索固定课程编号和专业术语；向量路径能检索至少三个不共享核心词的同义问题。
- [ ] 查询先应用 course/version/access 元数据边界，所有返回结果属于请求课程与用户权限。
- [ ] manifest 校验 source_checksum、chunk_policy、embedding_model、dimension 与 index_version；不一致拒绝加载。
- [ ] 验收证据包括构建日志、索引文件哈希、六问 Top-5、重启后同结果、损坏模拟和原子回滚记录。

## 任务分析

### 岗位任务、输入与输出

输入是稳定 Chunk JSONL、课程 ID、可索引元数据、分词配置、embedding 模型与批量参数；输出是两组持久化文件和统一命中列表。关键词分数与向量相似度数值不在同一尺度，本项目保留原始分数和各自排名，不直接相加。

## 核心知识

### BM25 的工程含义

BM25 根据查询词在文档中的出现、该词在语料中的稀有程度和文档长度进行相关性排序。它对课程编号、API 名称和法规术语等精确文字很有效。中文没有天然空格，必须选择分词器、字符 n-gram 或二者组合，并为领域词维护可版本化词典。停用词删除要通过问题集验证，某些看似常见的否定词不能删除。

### 向量检索与距离

embedding 将文本映射为固定维数向量，相近语义通常在选定距离函数下更接近。Faiss 提供稠密向量相似搜索与聚类索引。使用内积模拟余弦相似度时，查询与文档向量都需要一致归一化。embedding 模型、维度或文本前缀变化会使旧向量不可直接混用，必须重建或维护清晰版本分区。

### 映射和元数据过滤

向量索引常只保存数值 ID，需要单独的 `row_id -> chunk_id` 映射。任何删除、排序或增量更新都必须同步，否则命中会指错证据。课程、版本、生效状态与权限过滤应在受信任的检索层强制执行；只在生成提示中说“不要泄露”无法阻止受限 Chunk 已经进入上下文。

### 持久化与原子发布

构建先写临时版本目录，完成所有文件和 manifest 后再切换当前指针。加载时验证 checksum、数量、向量维度和配置；文件不完整或材料变更应标记 stale/failed，不能继续使用。上一个通过验收的索引版本保留以便回滚。索引是生成物，源 Markdown 与 Chunk 配置才是可审阅事实来源。

## 工程实现步骤

1. 读取 Chunk JSONL 并验证 course_id、唯一 chunk_id、非空文本和权限字段；按稳定 chunk_id 排序。
2. 对标题前缀与正文进行中文分词，记录 tokenizer/词典版本；构建词频、文档频率和长度统计。
3. 实现 BM25 search，返回 top_k 及原分数；用编号和否定词样例检查分词结果，必要时调整领域词典。
4. 批量生成 embedding，验证所有向量有限、维度一致；按选定距离执行同样的归一化策略。
5. 建立 Faiss 精确基线索引与 row 映射。规模增大前先保留精确基线，近似索引需另做召回/延迟比较。
6. 保存词法数据、向量索引、映射和 manifest；manifest 包含源 checksum、块策略、模型、维度、数量和创建时间。
7. 在版本临时目录加载自检，跑六问、权限与重启测试；全部通过后原子切换 current，失败则保留旧版。
8. 损坏映射或改变源 checksum，验证加载拒绝并给出可操作错误；记录构建日志和文件哈希。

## 关键代码与配置

向量与映射数量必须在加载时共同校验。

```python
import numpy as np

def normalize(rows: np.ndarray) -> np.ndarray:
    if rows.ndim != 2 or not np.isfinite(rows).all():
        raise ValueError("向量必须是有限二维数组")
    norms = np.linalg.norm(rows, axis=1, keepdims=True)
    if (norms == 0).any():
        raise ValueError("不能索引零向量")
    return rows / norms

def validate_mapping(ntotal: int, chunk_ids: list[str]) -> None:
    if ntotal != len(chunk_ids) or len(set(chunk_ids)) != len(chunk_ids):
        raise ValueError("向量索引与 Chunk 映射不一致")
```

## 调试和常见故障

### 故障案例一：课程编号被中文分词拆散

- **现象：** 查询 `AIE-204` 找不到标题含相同编号的块，普通中文术语却能命中。
- **原因：** 分词正则只保留汉字，删除了字母、连字符和数字，索引与查询均丢失编号。
- **定位：** 输出该查询和目标块的 token 列表，确认编号不存在；比较未经分词的原文。
- **修复：** 为字母数字连字符模式保留完整 token，并加入小写归一化和领域词典；建立编号检索回归。

### 故障案例二：向量命中指向错误段落

- **现象：** score 很高，返回的 chunk_id 文本却与查询完全无关；重建后错误位置变化。
- **原因：** 生成向量后又重新排序 Chunk，row 映射仍按旧顺序保存。
- **定位：** 对若干 row 同时计算文本哈希、chunk_id 和向量输入哈希，发现三者不一致。
- **修复：** 构建前稳定排序，向量与映射在同一循环生成；加载校验数量和输入哈希，禁止单独替换映射文件。

### 故障案例三：材料已更新仍加载旧索引

- **现象：** Markdown 中规则已经修订，搜索持续返回旧文字，服务状态却显示 ready。
- **原因：** 加载器只检查索引文件存在，没有对比当前 source_checksum 与 manifest。
- **定位：** 计算当前材料/Chunk 清单哈希，与 manifest 比较，确认不一致；检查状态判定分支。
- **修复：** checksum 不符标记 stale 并拒绝课程检索，触发显式重建；完成新版本自检后再原子切换。

## 安全、成本与职业规范提示

embedding 和索引可能泄露语料的存在与相似关系，应按源数据权限保护，备份和调试文件不能公开。查询过滤基于服务端身份和可信 metadata，不能接收客户端自报 `access=admin`。删除文档时需重建或可靠删除词法、向量、映射、缓存和备份中的派生数据。

真实 embedding 会产生费用和数据外传，先用本地 BM25/固定桩完成结构验收，再按授权批量调用并记录失败重试。近似索引在小规模不一定值得；应以基线 Recall@K、延迟、内存和构建时间选型。不要把 BM25 与向量原始 score 直接相加，下一项目将用排名融合解决尺度问题。

## 本项目小结

关键词与向量索引提供两种互补候选召回：BM25 擅长精确术语，向量擅长语义近邻。统一 SearchHit、可信元数据过滤、稳定映射和版本 manifest 使结果可追溯并可安全持久化。原子发布与 stale 校验避免新旧材料混用。下一项目将在不混加原始分数的前提下进行混合检索、查询改写和重排序。
