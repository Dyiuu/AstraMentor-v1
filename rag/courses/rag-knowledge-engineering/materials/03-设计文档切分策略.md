# 项目3：设计标题感知的文档切分策略

## 岗位情境

标准化文档已经保留标题、段落、表格和代码。开发者曾按每 500 个字符硬切，结果“禁止带电检修”的否定词落在上一块，操作步骤落在下一块；检索只返回步骤，模型给出了危险建议。另一份教材的表格被分成几块，行标题与数值失去对应。你需要设计标题感知、结构优先、长度受控的切分器，并用可视化统计与问题集验证切分质量。

切分的目标是形成可独立理解、可检索、可引用的证据单元，而不是追求统一长度。项目不训练 embedding，也不通过反复塞关键词迎合测试。

## 项目目标

- 能解释块粒度对召回、语义完整性、上下文冗余和引用精度的影响。
- 能利用 Markdown/PDF 标准块与章节路径进行标题感知切分。
- 能为重叠窗口、表格、代码、步骤和超长段落制定差异化规则。
- 能保留 chunk_id、document_id、section_path、位置范围与前后关系。
- 能用长度分布、断句检查和代表问题对多种策略做可重复比较。

## 项目产物与验收条件

产物为 `StructureAwareChunker`、策略配置、块清单和对比报告。

- [ ] 输入项目二的 Document，输出稳定有序 Chunk；相同输入和配置生成相同 chunk_id。
- [ ] 每块带章节面包屑、来源位置、字符/估算 Token 数与相邻块 ID。
- [ ] 标题不与首段分离，步骤清单、表格行和短代码块尽量保持完整；超限时按明确规则拆分。
- [ ] 重叠只复制必要边界上下文，并在 metadata 标明，避免引用重复计算。
- [ ] 验收证据包含三种策略、长度分布、十条人工检查、五问召回预检及选型理由。

## 任务分析

### 岗位任务、输入与输出

输入是带 blocks 与位置的 Document、目标/最大块长、最小块长、重叠上限和结构规则；输出是 Chunk 序列及质量报告。每个 Chunk 的正文应包含可读章节前缀，但来源定位仍指向真实 blocks。切分器不能修改原意或把不同权限、不同文档版本合并。

可复现实训选择含否定规则、七步操作、四列表格、Python 代码和超长段落的固定教材。实现字符定长、标题感知、结构感知加有限重叠三种策略。对十个重点位置人工标注“应同块/可分开”，统计违例；用五个自然问题进行 BM25 预检，但不以该小样本作为最终检索结论。

## 核心知识

### 粒度的双向代价

块过大包含更多上下文，但一个向量或关键词分数要代表多个主题，检索结果也会占用更多生成预算；块过小更精确，却可能丢失主语、条件、否定和章节背景。合理策略依据文档结构和真实问题，而不是照搬固定“最佳字符数”。目标长度用于常态分布，最大长度是保护边界，两者不能混为一项。

### 标题感知切分

标题路径提供块的主题语境。切分器遍历 blocks，标题变化时更新栈，把章节面包屑作为检索文本前缀或独立 metadata。短标题应与紧随的说明合并，不能成为只有几个字的孤立块。不同一级项目、不同文档或不同权限边界绝不合并，即使前后长度很短。

### 结构原子与超长处理

步骤列表中每步可能独立，但前置警告和共同条件应复制或与首块绑定。Markdown 表格至少保留表头与当前行；拆表时每个子块重复表头并标注 `table_part`。代码优先按函数或围栏分组，若超长才按语法安全点拆。普通长段先按句末，再按更小标点；任何拆分不能丢字符，拼回后应与规范化原文一致。

### 重叠窗口

重叠可缓解边界问题，却增加索引体积和重复结果。重叠应基于完整句或末尾少量 blocks，不按字符从词中间切。每块记录 `overlap_from`，检索和引用去重时识别重复区域。评价应比较“无重叠、有限重叠”的收益，而不是默认重叠越多越好。

## 工程实现步骤

1. 从需求问题集选出会受切分影响的五问，标注期望章节和必须共同出现的条件/结论。
2. 定义配置：目标 700 非空白字符、硬上限 1100、最小 120、重叠最多 120；这些是本样本起点而非通用真理。
3. 遍历标准 blocks，按 document/version/access 创建边界；维护 section_path，将标题上下文加入候选块。
4. 段落累计接近目标时在结构边界提交；过短相邻段只在同章节同权限下合并。
5. 对表格重复表头，对步骤绑定前置警告，对代码保留围栏语言和函数边界，对超长段按句拆分。
6. 从前一块末尾选择完整句作为有限重叠，写 overlap_from；生成基于 document_id、位置、策略版本的稳定 chunk_id。
7. 检查字符守恒、位置单调、最大长度、空块、标题孤块和重复率，输出分位数与异常样本。
8. 比较三策略的十条人工约束与五问 Top-5 预检，记录选型、失败案例和需要在索引项目继续验证的假设。

## 关键代码与配置

稳定 ID 来自来源位置与策略，不使用随机数。

```python
from hashlib import sha256

def chunk_id(doc_id: str, start: int, end: int, policy: str) -> str:
    raw = f"{doc_id}|{start}|{end}|{policy}".encode("utf-8")
    return sha256(raw).hexdigest()[:20]

def breadcrumb(path: list[str], text: str) -> str:
    title = " > ".join(item.strip() for item in path if item.strip())
    return f"章节：{title}\n{text.strip()}" if title else text.strip()
```

## 调试和常见故障

### 故障案例一：否定条件与操作步骤分离

- **现象：** 查询“能否带电检修”只返回操作步骤块，块内没有上一段“严禁带电”的前置警告。
- **原因：** 定长字符切分恰好在否定段后提交，且没有结构关联或完整句重叠。
- **定位：** 用 chunk_id 回到位置范围，查看相邻块与 section_path；在重点约束中检查警告和步骤应同块规则。
- **修复：** 把章节首个警告作为步骤组前缀，或以有限完整句重叠保留；加入自然问法的 Top-5 预检。

### 故障案例二：表格数值失去列名

- **现象：** 结果块只有 `220 | 10 | 合格`，模型无法知道三列含义。
- **原因：** 表格按字符切开，后续块没有重复表头，也没有 table_id/part 元数据。
- **定位：** 检查块类型与原表范围，拼接当前块时确认表头不在可见上下文。
- **修复：** 将表头作为每个表格子块的固定前缀，按完整行拆分并记录 table_part；引用仍定位到原行。

### 故障案例三：重叠导致搜索结果全是同一段

- **现象：** Top-5 中四条来自相邻块，核心句完全重复，其他文档证据被挤出。
- **原因：** 重叠设为块长一半且检索未按 document/overlap 去重。
- **定位：** 计算相邻块字符交并比与 overlap 字段，统计 Top-K 唯一来源数。
- **修复：** 将重叠降到边界完整句，记录来源并在结果层做近邻去重；用问题集比较 Recall 与多样性。

## 安全、成本与职业规范提示

切分不能跨权限和版本，否则一个块可能同时含公开与受限信息，后续过滤无法安全拆开。章节前缀不应复制个人姓名或隐私字段；必要元数据也要遵循最小化。引用显示重叠文本时应指向唯一原位置，避免让用户误以为多个来源相互印证。

更小块和更大重叠都会增加 embedding、存储和检索成本。调整前先保留基线，再用问题集量化收益。岗位报告必须呈现失败块与异常分布，不能只展示平均长度。策略版本与文档 checksum 绑定，变更后明确使对应索引过期。

## 实训练习

1. 在固定教材标注十个“应同块/可分开”位置，至少覆盖否定、步骤、表格和代码。
2. 实现三种策略并输出 P10/P50/P90、最大长度、空块数、重复率和唯一章节数。
3. 做字符守恒测试：去除人为章节前缀与标记后，块的非重叠内容可按位置还原规范化原文。
4. 复现表头丢失和过度重叠，保存故障结果，再用结构规则和去重修复。
5. 用五个自然问题做 Top-5 预检，提交策略选型、限制、配置、命令和十条人工审阅证据。

## 本项目小结

标题感知切分把标准文档转成既可独立理解又能回到证据位置的检索单元。目标长度只是约束之一，章节、否定条件、步骤、表格和代码等结构原子更决定语义是否完整。有限重叠要有来源并验证收益。下一项目将为这些稳定 Chunk 建立 BM25 与向量索引，并处理索引持久化和版本一致性。
