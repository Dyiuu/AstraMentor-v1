# AstraMentor AI 职业教育课程群扩展设计

> 状态：已通过需求与设计确认，等待规格审阅  
> 日期：2026-08-20  
> 范围：在现有“智能体设计与应用开发基础”课程之外新增四门 AI 应用工程课程，并扩展课程元数据、RAG 隔离与前端课程展示能力。

## 1. 背景

AstraMentor 已具备文件型课程注册、Markdown 教材切分、课程独立索引、知识星图、教学问答、学习评价和学习历史等能力。目前课程库只有“智能体设计与应用开发基础”，内容以 Coze 低代码实践为主。

本轮需要把项目扩展为面向 AI 职业教育的多课程 MVP，并明确加入“Agent 开发工程师”课程。新增课程应服务学生自主学习，强调岗位任务、工程实践、故障排查和可验收项目，而不是仅提供概念性知识问答。

## 2. 目标

1. 新增四门课程，与现有课程组成五门 AI 职业教育课程群。
2. 每门新课包含 8 个项目化单元、约 32 学时，共 32 个 Markdown 项目文件。
3. “Agent 开发工程师”采用代码工程路线，与现有 Coze 低代码课程清晰区分。
4. 核心示例采用原生 Python 和 OpenAI 兼容 API，可适配项目当前的 OpenRouter/Gemini 配置。
5. 使用元数据描述学时、难度、岗位、能力、先修能力、推荐课程和综合项目。
6. 每门课程拥有独立 RAG 索引，检索结果不得跨课程混入。
7. 保持未来扩展简单：新增课程主要通过增加课程目录、清单和 Markdown 文件完成。
8. 前端能够清晰展示课程职业定位，并在压缩窗口和夜间模式下保持可读。

## 3. 非目标

本轮不包含以下内容：

- 不建设完整 LMS、数据库课程管理后台、教师排课或作业批改系统。
- 不在新课程中重复教授 Python 语法、Git、HTTP、JSON 或 Linux 基础。
- 不强制锁定课程学习顺序，先修课程仅作为推荐。
- 不将课程绑定到单一模型厂商、单一 Agent 框架或单一云平台。
- 不重写现有 Coze 低代码教材；仅在必要时补充课程元数据。
- 不把生成索引当作教材源文件，教材仍以版本可追踪的 Markdown 为准。

## 4. 已确认设计决策

- 内容来源：由项目编写原创职业教育材料，而不是等待用户提供教材。
- 首批规模：新增 4 门课程，连同现有课程形成 5 门核心课程。
- 学习者基础：已具备 Python、API、Git 和基本 Linux 能力。
- Agent 路线：代码工程路线，覆盖工具、记忆、RAG、工作流、MCP、多智能体、评测与部署。
- 单课规模：8 个项目化单元、约 32 学时。
- 技术路线：原生 Python + OpenAI 兼容 API 为核心，LangGraph、Google ADK、MCP 等为进阶内容。
- 扩展方式：课程元数据驱动，不引入完整教学管理数据库。

## 5. 课程群与学习路径

| 展示顺序 | 课程 ID | 课程名称 | 定位 | 主要岗位方向 |
|---:|---|---|---|---|
| 10 | `agent-design` | 智能体设计与应用开发基础 | 现有 Coze 低代码并行入口 | 智能体产品助理、低代码应用开发 |
| 20 | `llm-app-development` | 大模型应用开发 | 模型调用与 AI 应用服务 | 大模型应用开发工程师 |
| 30 | `rag-knowledge-engineering` | RAG 知识库工程 | 数据处理、检索与答案评测 | RAG 工程师、知识库工程师 |
| 40 | `agent-engineering` | Agent 开发工程师 | 多步骤自主执行与系统编排 | Agent 开发工程师 |
| 50 | `ai-app-production` | AI 应用测试、部署与安全 | AI 系统质量与生产化 | AI 测试工程师、AI 应用运维工程师 |

推荐代码学习路径：

```text
大模型应用开发
       ↓
RAG 知识库工程
       ↓
Agent 开发工程师
       ↓
AI 应用测试、部署与安全
```

“智能体设计与应用开发基础”是并行低代码入口，不是代码路线的强制前置课。前端只展示推荐顺序和先修信息，不限制学生自主进入课程。

进入带有 `prerequisite_skills` 的代码课程时，前端把当前水平设置为“已具备：<先修能力列表>”，知识星图生成提示明确要求不得把这些先修能力再次生成为学习节点。缺少先修元数据的旧课程继续使用现有“零基础”默认值。

| 5. 优化召回结果 | 混合检索、过滤、查询改写和重排 | 混合检索服务 |

| 项目 | 岗位任务 | 核心产物 |
|---|---|---|
| 1. 制定质量标准 | 定义业务目标、指标、风险等级和测试集 | AI 验收方案 |

| 4. 建立可观测体系 | 记录日志、Trace、Token、延迟和错误链路 | 可观测仪表数据 |
| 5. 防御 AI 应用风险 | 防范提示注入、越权、敏感数据和不安全输出 | 安全护栏与审计清单 |

## 7. 单元教材模板

每个 Markdown 项目文件使用一致结构：

1. 岗位情境
2. 项目目标
3. 项目产物与验收条件
4. 任务分析
5. 核心知识
6. 工程实现步骤
7. 关键代码与配置
8. 调试和常见故障
9. 安全、成本与职业规范提示
10. 实训练习
11. 学习评价量表
12. 本项目小结
13. 官方参考资料与核验日期

写作要求：

- 内容必须为 AstraMentor 原创教学表述，不复制第三方教材或官方文档正文。
- 标题包含明确技术实体和任务语义，避免使用“其他”“补充”等无上下文标题，以提升 RAG 切分质量。
- 一个关键结论尽量在同一章节内给出定义、适用条件和失败边界。
- 代码片段应完整到足以理解输入、输出和错误处理，省略部分必须明确标注。
- 示例只使用诸如 `YOUR_API_KEY` 的占位符，禁止写入真实密钥。
- 模型名通过环境变量配置，不依赖某个模型永久支持特定能力。
- 涉及工具执行时明确区分“模型请求调用工具”和“应用已经执行工具”。
- 可能产生真实外部副作用的操作必须说明权限、确认和最小授权原则。
- 每个单元末尾记录资料核验日期；首版统一为 2026-08-20。

### 9.1 校验与兼容

- `order` 必须是非负整数。
- `hours` 必须是非负整数，新课程固定为 32。
- `level` 必须属于允许值集合。
- 所有数组字段必须为非空字符串数组，允许整体缺省。
- `recommended_courses` 中的值必须符合安全课程 ID 格式。
- 推荐课程暂时未安装时只产生维护警告，不阻止当前课程加载。
- 现有 `agent-design` 清单缺少新增字段时使用默认值，仍可正常加载。
- 本轮为现有 `agent-design` 清单补充 `order: 10`；其他职业元数据只有在能够从现有教材可靠确认时才填写。
- 无法确认现有课程学时时不编造数值，前端显示“学时待定”或省略该徽标。
- 一个课程清单无效时继续加载其他有效课程。

## 10. 后端与 RAG 设计

### 10.1 注册表

`rag/course_registry.py` 的 `Course` 数据结构负责解析和输出新增元数据。`list_courses()` 按 `(order, title)` 排序，而不是只按标题排序。

注册表继续遵循容错原则：无效课程不会隐藏有效兄弟课程。结构错误进入错误集合；仅影响维护体验但不影响运行的跨课程推荐问题进入警告集合。

### 10.2 API

沿用现有课程接口，不新增课程专用硬编码：

- `GET /api/courses`：课程对象增加职业教育元数据和当前索引状态；顶层增加 `course_warnings` 供维护者发现不存在的推荐课程等非致命问题。
- `GET /api/courses/{course_id}`：作为单门课程索引构建状态的轮询接口。
- 现有单课程索引构建接口保持不变。
- 现有课程搜索接口保持不变，并继续由 URL 中的 `course_id` 决定索引范围。

前端和后端对新增字段采用可选或默认值策略，避免旧数据导致页面崩溃。

索引状态统一为 `ready`、`missing`、`stale`、`building` 或 `failed`。后台构建发生异常时返回 `failed` 和可展示的错误信息，而不是继续保留为不明确的 `missing`/`stale` 状态。重试构建时清除上一次失败信息。

### 10.3 索引隔离

```text
course.yaml ───────→ CourseRegistry ─────→ /api/courses ─────→ CourseCatalog
                          │
Markdown 项目文件 ───────→ Indexer ───────→ rag/indexes/<course-id>/
                                                    │
请求中的 course_id ───────────────────────────────→ Retriever
                                                    │
                                                    ├→ 知识星图
                                                    ├→ 教学讲解
                                                    ├→ 对话问答
                                                    └→ 学习评价与引用
```

隔离约束：

- 索引目录固定为 `rag/indexes/<course-id>/`。
- 在课程模式中，知识星图、开始学习、对话、重教和评价请求始终携带同一个 `course_id`；主题、项目和文档模式继续保持原有可选行为。
- Retriever 只能打开请求课程的索引目录。
- 引用继续记录课程 ID、教材标题、章节路径、文件、行号和检索分数。
- 学习历史继续持久化课程 ID 和课程标题，恢复后不得切换到当前目录中的其他课程。
- 某课程 Markdown 变化时只将该课程索引标记为过期。

### 10.4 无可靠证据时的行为

当指定课程没有索引、索引已失效或检索不到足够相关内容时：

1. 不静默切换到其他课程索引。
2. `missing`、`stale` 或 `failed` 时，课程模式的星图生成、教学、对话、重教和评价接口返回结构化 HTTP 409 `course_index_not_ready`，不得自动建索引，也不得跳过 RAG 后继续调用模型。
3. 前端根据 409 中的 `course_id`、状态和消息提示构建、重建或重试对应课程。
4. 只有索引处于 `ready` 但本次查询没有足够相关结果时，才可按既有策略使用模型扩展知识；响应必须标记为扩展内容，不能伪装为教材证据。
5. 无法可靠回答教材问题时明确说明证据不足。

## 11. 前端设计

### 11.1 类型

前端 `Course` 类型同步加入新增元数据字段。数组字段使用空数组兜底，数字和枚举字段使用安全默认值。

### 11.2 课程卡片

课程卡片显示：

- 课程类别与版本
- 课程名称和简短描述
- 学时与难度
- 最多两个主要岗位或标签
- 一行“推荐先修：<课程标题>”；没有推荐课程时省略
- 教材数量和索引状态
- 进入课程或构建索引按钮

每张卡片使用原生 `<details>`/`<summary>` 展示完整先修能力、能力目标和综合项目，不新增详情页或路由。卡片必须限制描述行数，标签使用 `flex-wrap`，按钮保持在卡片底部。

首次点击“构建课程索引”后，前端每秒轮询 `GET /api/courses/{course_id}`，直到状态变为 `ready` 或 `failed`。`ready` 后直接进入该课程；`failed` 时显示错误和重试按钮。轮询超过 120 秒后停止主动等待并提示索引仍在构建，用户可以手动刷新状态，避免无限等待。

### 11.3 响应式与夜间模式

- 课程网格使用自适应列和合理最小宽度，窗口变窄时减少列数，而不是继续压缩卡片内容。
- 卡片内部不依赖固定宽度；长标题、岗位名和标签允许换行。
- 夜间模式的标题、正文、次要文字、徽标和边框均使用已有主题变量，并满足明显的前景/背景对比。
- 加载、索引构建失败和空课程状态在日间、夜间模式下都应清晰可见。

## 13. 错误处理

| 场景 | 预期行为 |
|---|---|
| 课程清单语法错误 | 隐藏该课程，记录具体清单路径和错误；其他课程正常加载 |
| Markdown 文件缺失 | 该课程校验失败，不生成空索引 |
| 材料路径越过课程目录 | 视为安全错误并拒绝加载 |
| 推荐课程不存在 | 当前课程继续加载，记录维护警告 |
| 索引缺失或过期 | 课程卡片显示构建/重建操作 |
| 单课索引构建失败 | 状态进入 `failed`，显示可重试错误，其他课程保持可用 |
| 课程模式在索引未就绪时发起学习请求 | 返回结构化 409，不自动建索引或绕过 RAG 调用模型 |
| 检索结果不足 | 标记证据不足或扩展知识，不伪造教材引用 |
| 模型不支持某项能力 | 使用教材中说明的降级路线或给出明确能力错误 |
| API 超时或限流 | 有限重试、退避和用户可理解错误，不无限等待 |

## 14. 测试与验收

### 14.1 注册表测试

- 新字段能够正确解析和序列化。
- 旧清单缺少新字段时使用默认值。
- 课程按 `order` 后按标题稳定排序。
- 错误类型、非法列表、非法推荐课程 ID 被正确处理。
- 无效课程不影响其他有效课程。
- 不存在的推荐课程进入 `course_warnings`，但不阻止当前课程加载。

### 14.2 索引测试

- 四门新课程各自构建成功且 `chunk_count > 0`。
- 每个索引中的所有块都携带正确 `course_id`。
- 修改一个课程文件只使该课程索引变为过期。
- 文件名、章节路径和行号可以回溯到原 Markdown。
- 后台构建异常进入 `failed`，重新构建能够清除旧错误并恢复为 `ready`。

### 14.3 检索验收集

每门课至少设置 5 个代表性问题，共不少于 20 个用例：

- 大模型应用开发：结构化输出、Token 预算、多模态校验、工具参数、流式取消。
- RAG 知识库工程：标题切分、混合检索、重排序、引用拒答、召回评测。
- Agent 开发工程师：循环终止、工具错误恢复、记忆边界、MCP 架构、多 Agent 移交。
- 测试部署安全：回归集、Trace、提示注入、最小权限、容器健康检查。

每个用例至少验证：

1. 结果来自指定课程。
2. Top-K 中包含预期项目或章节。
3. 引用文件和行号有效。
4. 不出现其他课程的证据块。

### 14.4 API 与前端测试

- `GET /api/courses` 返回所有课程及完整元数据。
- 单课程索引构建和搜索接口保持兼容。
- 首次构建从 `building` 轮询到 `ready` 后自动进入课程；`failed` 和 120 秒超时均停止轮询并提供恢复操作。
- `missing`、`stale`、`failed` 状态下，课程模式的星图、教学、对话、重教和评价均返回 409，且不会调用模型。
- 课程卡片能处理旧课程默认值和新课程完整值。
- 推荐课程 ID 能够映射为课程标题，完整先修能力、能力目标和综合项目通过卡片内 `<details>` 展示。
- 新代码课程生成星图时，`current_level` 来自 `prerequisite_skills`，生成提示明确排除先修能力节点；旧课程维持兼容默认值。
- 从星图生成、开始学习、对话、测验、评价到历史恢复，课程模式始终使用最初选择的同一 `course_id`。
- 桌面宽度、压缩窗口和夜间模式下无重叠、溢出或低对比文字。
- 前端类型检查、Lint 和生产构建通过。
- 后端现有测试与新增测试全部通过。

### 14.5 教材结构检查

对 32 个项目文件执行自动结构检查：

- 包含岗位情境、项目目标、项目产物与验收条件、任务分析、核心知识、工程实现、调试与常见故障、实训练习、学习评价量表、小结、官方参考资料和核验日期。
- 不包含 `TODO`、`TBD`、“待补充”等未完成占位内容。
- 至少包含一个可检查的工程产物或配置产物，不能只有概念说明。
- 技术参考链接使用官方文档、标准或原始研究资料。
- 不包含常见 API Key、访问令牌或个人凭据格式。

## 16. 主要风险与控制

| 风险 | 控制措施 |
|---|---|
| 32 个项目内容过于简略 | 使用统一项目模板和可验收产物；逐门检查覆盖度 |
| 课程之间内容重复 | 维持模型调用、RAG、Agent 编排、生产化四层边界 |
| 技术资料快速过时 | 记录核验日期、使用环境变量、优先通用协议和能力检测 |
| 多课程检索串库 | 以 `course_id` 选择唯一索引目录并加入负向测试 |
| 卡片信息过多导致拥挤 | 卡片只显示摘要，详情延后展示，网格随宽度换列 |
| 教材包含真实凭据 | 仅使用占位符，并在检查中搜索常见密钥格式 |
| Agent 工具权限过大 | 强调最小权限、参数校验、人工确认、日志和可中断性 |

## 17. 后续扩展约定

未来新增课程时，应只需要：

1. 创建安全、稳定的课程 ID 目录。
2. 编写完整 `course.yaml`。
3. 添加一个或多个 Markdown 教材文件。
4. 运行注册表校验和课程索引构建。
5. 添加该课程的代表性检索验收问题。

只要新课程使用现有元数据字段，核心后端和前端不应再增加课程名称硬编码。
